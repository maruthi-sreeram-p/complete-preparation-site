?1 [Processes and threads] Which of the following instructions should be executed only in kernel (privileged) mode?
(a) adding two registers
(b)* disabling interrupts
(c) loading an immediate value into a register
(d) reading a local variable from the stack
=> Disabling interrupts, setting the timer and changing memory-protection registers could let a user program take over the machine, so they are privileged. Ordinary arithmetic and loads are not.

?2 [Processes and threads] How many times is X printed by the following program (assume every fork succeeds)?
```c
int main(void) {
    for (int i = 0; i < 3; i++) fork();
    printf("X");
    return 0;
}
```
(a) 3
(b) 6
(c)* 8
(d) 16
=> Each fork doubles the number of running processes. After 3 iterations there are 2³ = 8 processes, and each of them executes the printf once.
!py assert num(ans) == 2 ** 3

?2 [Processes and threads] How many times is A printed by the following program (assume every fork succeeds)?
```c
int main(void) {
    if (fork() == 0) { fork(); }
    printf("A");
    return 0;
}
```
(a) 2
(b)* 3
(c) 4
(d) 6
=> The parent skips the if body and prints once. The child (fork returned 0) forks again, and the child and the grandchild each print once. Total 1 + 2 = 3.

?1 [Processes and threads] A process moves from the running state to the ready state when
(a) it requests an I/O operation
(b)* its time slice expires or a higher-priority process preempts it
(c) its I/O operation completes
(d) it terminates
=> A running process that is still able to run but has lost the CPU returns to the ready queue. A request for I/O would send it to the waiting state.

?2 [Processes and threads] Which of the following is NOT shared among the threads of a single process?
(a) the heap
(b) global variables
(c) open file descriptors
(d)* the stack
=> Each thread has its own stack, registers and program counter so that it can run independently. Code, global data, the heap and open files are shared by all threads of the process.

?2 [Processes and threads] A process uses many-to-one user-level threads. One of its threads makes a blocking system call. As a result
(a)* all the threads of the process are blocked
(b) only that thread is blocked
(c) the process is terminated
(d) the other threads run on other CPUs
=> The kernel knows only about the process, so it blocks the whole process. This is one disadvantage of user-level threads compared with kernel threads.

?1 [Processes and threads] A process that has terminated but whose parent has not yet called wait() is called a
(a) orphan
(b)* zombie
(c) daemon
(d) thread
=> A zombie keeps its entry in the process table so the parent can collect its exit status. An orphan is a running child whose parent has died.

?1 [Processes and threads] Which inter-process communication mechanism is generally the fastest once it has been set up?
(a) pipes
(b) message queues
(c)* shared memory
(d) sockets
=> With shared memory, processes read and write the same region directly with no system call per message. The others copy data through the kernel (but are easier to use safely).

?1 [CPU scheduling] As the time quantum of round-robin scheduling becomes very large, the algorithm behaves like
(a)* first-come first-served
(b) shortest-job-first
(c) priority scheduling
(d) multilevel feedback queue
=> If the quantum exceeds every burst, each process runs to completion in arrival order once it gets the CPU, which is FCFS.

?1 [CPU scheduling] The convoy effect, in which many short processes wait behind one long process, is associated with
(a)* first-come first-served scheduling
(b) round-robin scheduling
(c) shortest-remaining-time-first scheduling
(d) multilevel feedback queues
=> FCFS is non-preemptive and orders processes by arrival, so a long CPU burst at the front delays everything behind it.

(a) deadlock
(b) thrashing
(c)* starvation
(d) priority inversion
=> In priority scheduling a low-priority process may never run. Raising its priority as it waits guarantees that it eventually gets the CPU.

?2 [Memory management] The free memory holes, in address order, are 150K, 400K, 250K and 600K. Four requests arrive in this order: 200K, 120K, 350K and 500K. Which placement strategy can satisfy all four requests?
(a) first fit
(b)* best fit
(c) worst fit
(d) none of them
=> Best fit puts 200K in the 250K hole, 120K in the 150K hole, 350K in the 400K hole and 500K in the 600K hole. First fit wastes the 400K and 600K holes on the first requests, leaving nothing big enough for 500K.
!py
def place(holes, requests, policy):
    holes = list(holes)
    for r in requests:
        fits = [i for i, h in enumerate(holes) if h >= r]
        if not fits:
            return False
        i = fits[0] if policy == 'first' else min(fits, key=lambda i: holes[i]) if policy == 'best' else max(fits, key=lambda i: holes[i])
        holes[i] -= r
    return True
H, R = [150, 400, 250, 600], [200, 120, 350, 500]
assert place(H, R, 'best') and not place(H, R, 'first') and not place(H, R, 'worst')
