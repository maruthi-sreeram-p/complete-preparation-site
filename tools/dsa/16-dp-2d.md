## The idea

2-D DP is the same recipe as 1-D DP (state, transition, base case, order) with **two changing quantities** in the state, so the table has two dimensions: a position in two strings (`dp[i][j]`), a grid cell, or an item index and a remaining capacity.

| Family | State `dp[i][j]` | Transition idea | Problems |
|---|---|---|---|
| **Grid paths** | Ways or cost to reach cell (i, j) | From the cell above or to the left | Unique Paths |
| **Two strings** | Answer for the first i characters of A and first j of B | Characters equal: take the diagonal; else best of dropping one | Longest Common Subsequence, Edit Distance, Interleaving String, Distinct Subsequences |
| **Knapsack** | Using the first i items with capacity j | Take the item or leave it | Coin Change II, Target Sum, Partition Equal Subset Sum |
| **Intervals** | Best for the range i..j | Try every split point k | Burst Balloons |
| **Matching** | Do the first i of the text match the first j of the pattern | Cases for `.` and `*` | Regular Expression Matching |

!tip Signal words :: "two strings", "subsequence", "edit", "match", "grid with obstacles", "knapsack", "target sum with each item once", "interleave". Whenever the input is two sequences and you compare prefixes, think `dp[i][j]`.

**Drawing the table** on paper with the base row and column filled in, and shading which cells each cell depends on, is the fastest way to find the transition and the loop order. If `dp[i][j]` only reads the previous row, keep **one row** and cut memory from O(n·m) to O(m).

## The Java toolkit and templates

```java Dp2d.java
import java.util.*;

public class Dp2d {

    /** Unique Paths: each cell is reached from above or from the left. One row is enough. */
    static int uniquePaths(int rows, int cols) {
        int[] row = new int[cols];
        Arrays.fill(row, 1);                                 // the first row has exactly one path to each cell
        for (int r = 1; r < rows; r++) {
            for (int c = 1; c < cols; c++) {
                row[c] += row[c - 1];                        // row[c] already holds "from above"; add "from the left"
            }
        }
        return row[cols - 1];
    }

    /** Longest Common Subsequence: dp[i][j] for the first i characters of a and the first j of b. */
    static int longestCommonSubsequence(String a, String b) {
        int[][] dp = new int[a.length() + 1][b.length() + 1];            // row 0 and column 0 are the empty prefixes
        for (int i = 1; i <= a.length(); i++) {
            for (int j = 1; j <= b.length(); j++) {
                dp[i][j] = a.charAt(i - 1) == b.charAt(j - 1)
                        ? dp[i - 1][j - 1] + 1                           // the characters match: extend the diagonal
                        : Math.max(dp[i - 1][j], dp[i][j - 1]);          // skip one character of either string
            }
        }
        return dp[a.length()][b.length()];
    }

    /** Edit Distance: the fewest insertions, deletions and replacements to turn a into b. */
    static int editDistance(String a, String b) {
        int n = a.length(), m = b.length();
        int[][] dp = new int[n + 1][m + 1];
        for (int i = 0; i <= n; i++) dp[i][0] = i;                       // delete all i characters
        for (int j = 0; j <= m; j++) dp[0][j] = j;                       // insert all j characters
        for (int i = 1; i <= n; i++) {
            for (int j = 1; j <= m; j++) {
                dp[i][j] = a.charAt(i - 1) == b.charAt(j - 1)
                        ? dp[i - 1][j - 1]
                        : 1 + Math.min(dp[i - 1][j - 1], Math.min(dp[i - 1][j], dp[i][j - 1]));   // replace, delete, insert
            }
        }
        return dp[n][m];
    }

    /** Coin Change II: the number of combinations. Coins in the OUTER loop counts each combination once. */
    static int change(int amount, int[] coins) {
        int[] ways = new int[amount + 1];
        ways[0] = 1;
        for (int coin : coins) {
            for (int a = coin; a <= amount; a++) {
                ways[a] += ways[a - coin];
            }
        }
        return ways[amount];
    }

    /** Partition Equal Subset Sum: 0/1 knapsack on a boolean row. Loop the sum DOWNWARDS so each number is used once. */
    static boolean canPartition(int[] nums) {
        int total = 0;
        for (int n : nums) total += n;
        if (total % 2 != 0) return false;
        int target = total / 2;
        boolean[] reachable = new boolean[target + 1];
        reachable[0] = true;
        for (int n : nums) {
            for (int sum = target; sum >= n; sum--) {
                reachable[sum] |= reachable[sum - n];
            }
        }
        return reachable[target];
    }
}
```

**What to notice.** Two loop-direction rules decide correctness. For **combinations** (Coin Change II) put the coins in the outer loop; swapping the loops counts *permutations* (1+2 and 2+1 as different). For **0/1 knapsack** with a one-row table, iterate the capacity *downwards* so an item cannot be used twice; for **unbounded** knapsack (coins reusable) iterate upwards.

## Pitfalls and interview angle

- **Off-by-one between string index and table index.** Row `i` is "the first i characters", so the character is `charAt(i - 1)`.
- **Missing base row and column.** Edit Distance needs `dp[i][0] = i` and `dp[0][j] = j`, not zeros.
- **Wrong loop order** when compressing to one row (see above).
- **Memory.** A 5000 x 5000 `int` table is 100 MB. Keep two rows when only the previous row is read.
- **Recovering the actual answer** (the subsequence, the edit script) needs the full table, walked backwards from `dp[n][m]`.

!interview Interview angle: Explain the recurrence for edit distance. :: `dp[i][j]` is the fewest operations to turn the first i characters of A into the first j of B. If the last characters match, nothing is needed: `dp[i-1][j-1]`. Otherwise take one plus the best of replacing the last character (`dp[i-1][j-1]`), deleting from A (`dp[i-1][j]`) or inserting into A (`dp[i][j-1]`). The base cases are converting to or from the empty string.

!keypoints 2-D DP is the 1-D recipe with two state variables: draw the table and mark its dependencies ;; Strings: `dp[i][j]` is about the first i and first j characters; use `charAt(i - 1)` ;; Fill the base row and column deliberately ;; Combinations need the items in the outer loop; 0/1 knapsack loops capacity downwards ;; Keep one row when only the previous row is read ;; Rebuilding the actual answer needs the whole table

?? Why does Coin Change II put the coin loop outside and the amount loop inside?
=> Processing one coin at a time allows only combinations in non-decreasing coin order, so each combination is counted once. With the amount loop outside, the same coins in different orders would be counted separately.

?? Why must the 0/1 knapsack's inner loop run downwards?
=> `reachable[sum - n]` must still refer to the state *before* this item was considered. Running upwards would already include the item, letting it be used several times, which is the unbounded problem.

?? What is the time and space of Longest Common Subsequence and how can the space shrink?
=> O(n·m) time and space. Because each row only reads the previous row, two rows (or one row plus a variable for the diagonal) bring the space down to O(min(n, m)); you then lose the ability to reconstruct the subsequence.
