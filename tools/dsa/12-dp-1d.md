## The idea

Dynamic programming (DP) solves a problem by combining answers to **smaller versions of the same problem**, solving each smaller version only once. It applies when two properties hold: the problem has **overlapping subproblems** (plain recursion would recompute the same thing many times) and **optimal substructure** (the best answer is built from best answers to subproblems).

A simple recipe works for every DP problem:

1. **Define the state**: what does `dp[i]` mean, in one sentence? ("the maximum money from the first i houses").
2. **Write the transition**: how does `dp[i]` follow from smaller states? ("`max(dp[i-1], dp[i-2] + nums[i])`").
3. **Set the base cases**: the smallest states you know directly.
4. **Choose the order and the answer**: usually left to right, answer in `dp[n]` or the maximum of the table.
5. **Optimise memory** if `dp[i]` only needs the last one or two values.

| Style | How | When it is nicer |
|---|---|---|
| **Top-down** (memoisation) | Recursive function plus a cache | When not every state is needed, or the recurrence is natural to write |
| **Bottom-up** (tabulation) | Fill an array in order | No recursion depth limit, usually faster, easier to reduce memory |

!tip Signal words :: "number of ways", "minimum cost", "maximum", "can you reach / partition / form", "longest", on a sequence where each element's best answer depends on earlier ones. If a greedy choice is not obviously correct and brute force repeats work, think DP.

## The Java toolkit and templates

```java Dp1d.java
import java.util.*;

public class Dp1d {

    /** House Robber: at each house either rob it (plus the best two houses back) or skip it. Two variables suffice. */
    static int rob(int[] nums) {
        int take = 0, skip = 0;                              // best total if the last house was robbed / not robbed
        for (int money : nums) {
            int newTake = skip + money;
            skip = Math.max(skip, take);
            take = newTake;
        }
        return Math.max(take, skip);
    }

    /** Climbing Stairs: ways(i) = ways(i-1) + ways(i-2), the Fibonacci recurrence. */
    static int climbStairs(int n) {
        int a = 1, b = 1;
        for (int i = 2; i <= n; i++) {
            int c = a + b;
            a = b;
            b = c;
        }
        return b;
    }

    /** Coin Change: dp[a] = fewest coins to make amount a. Unreachable amounts hold a value larger than any answer. */
    static int coinChange(int[] coins, int amount) {
        int[] dp = new int[amount + 1];
        Arrays.fill(dp, amount + 1);                         // "infinity" that cannot overflow when we add 1
        dp[0] = 0;
        for (int a = 1; a <= amount; a++) {
            for (int coin : coins) {
                if (coin <= a) dp[a] = Math.min(dp[a], dp[a - coin] + 1);
            }
        }
        return dp[amount] > amount ? -1 : dp[amount];
    }

    /** Word Break: dp[i] is true if the first i letters can be split into dictionary words. */
    static boolean wordBreak(String s, Set<String> dictionary) {
        boolean[] dp = new boolean[s.length() + 1];
        dp[0] = true;                                        // the empty prefix is fine
        for (int i = 1; i <= s.length(); i++) {
            for (int j = 0; j < i; j++) {
                if (dp[j] && dictionary.contains(s.substring(j, i))) {
                    dp[i] = true;
                    break;
                }
            }
        }
        return dp[s.length()];
    }

    /** Longest Increasing Subsequence in O(n log n): tails[k] = smallest tail of an increasing run of length k+1. */
    static int lengthOfLIS(int[] nums) {
        int[] tails = new int[nums.length];
        int size = 0;
        for (int n : nums) {
            int i = Arrays.binarySearch(tails, 0, size, n);
            if (i < 0) i = -(i + 1);                         // insertion point
            tails[i] = n;
            if (i == size) size++;
        }
        return size;
    }

    /** Maximum Product Subarray: a negative can turn the smallest product into the largest, so track both. */
    static int maxProduct(int[] nums) {
        int max = nums[0], min = nums[0], best = nums[0];
        for (int i = 1; i < nums.length; i++) {
            int n = nums[i];
            int hi = Math.max(n, Math.max(max * n, min * n));
            int lo = Math.min(n, Math.min(max * n, min * n));
            max = hi;
            min = lo;
            best = Math.max(best, max);
        }
        return best;
    }

    /** The same Fibonacci-style recurrence, top-down with a memo. */
    static long fibMemo(int n, long[] memo) {
        if (n <= 1) return n;
        if (memo[n] != 0) return memo[n];
        return memo[n] = fibMemo(n - 1, memo) + fibMemo(n - 2, memo);
    }
}
```

**What to notice.** `rob` and `climbStairs` keep only the previous one or two states, so the space drops from O(n) to O(1). The `lengthOfLIS` method is not a "classic DP table" but is the standard O(n log n) answer: `tails` is always sorted, so a binary search finds where each number belongs.

## Pitfalls and interview angle

- **A vague state definition.** If you cannot say what `dp[i]` means in a sentence, the transition will be wrong.
- **Wrong base cases or off-by-one** between 0-based strings and 1-based tables (`dp[i]` for "the first i characters").
- **Using `Integer.MAX_VALUE` as infinity** and then adding 1 to it: it overflows to a negative number. Use `amount + 1` or check before adding.
- **Greedy is not DP.** Coin change with coins {1, 3, 4} and amount 6: greedy picks 4+1+1 (3 coins), the optimum is 3+3 (2 coins).
- **Deep recursion** for top-down with n around 10⁵ overflows the stack; switch to bottom-up.

!interview Interview angle: How do you decide between top-down and bottom-up? :: Top-down is quicker to write when the recurrence is natural and not every state is needed, but it uses the call stack and has function-call overhead. Bottom-up avoids recursion limits, is usually faster, and makes it easy to cut memory by keeping only the last few rows. In an interview, start with the recurrence, then say which you will implement and why.

!keypoints Define the state in one sentence, write the transition, set the base cases ;; DP = overlapping subproblems + optimal substructure ;; Top-down is recursion plus a cache; bottom-up fills a table in order ;; Keep only the states the next step needs to save memory ;; Use `amount + 1` instead of `Integer.MAX_VALUE` as infinity ;; Greedy can fail where DP succeeds: coin change is the classic example

?? What does `dp[i]` mean in the coin change problem and what is the transition?
=> `dp[a]` is the fewest coins needed for amount a. The transition is `dp[a] = min(dp[a - coin] + 1)` over all coins not larger than a, with `dp[0] = 0`.

?? Why does House Robber only need two variables?
=> The best total for the first i houses depends only on the best totals for the first i-1 and i-2 houses, so the older table entries are never read again.

?? Why does Maximum Product Subarray track both a maximum and a minimum?
=> Multiplying by a negative number swaps them: the most negative product becomes the largest positive one. Keeping the minimum lets a later negative element rescue it.
