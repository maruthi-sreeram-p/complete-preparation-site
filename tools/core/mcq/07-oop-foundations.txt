?1 [Pillars] Declaring a class's fields private and providing public methods that validate every change illustrates
(a) inheritance
(b)* encapsulation
(c) polymorphism
(d) method overloading
=> Encapsulation restricts direct access to an object's state and exposes controlled operations, so the class can enforce its invariants. Inheritance and polymorphism concern class hierarchies and run-time method selection.

?2 [Static and instance] What does this program print?
```java
public class Main {
    static class Counter {
        static int count;
        int id;
        Counter() { id = ++count; }
    }
    public static void main(String[] args) {
        new Counter();
        new Counter();
        Counter c = new Counter();
        System.out.println(c.id + " " + Counter.count);
    }
}
```
(a) 1 3
(b)* 3 3
(c) 3 1
(d) 1 1
=> `count` is static, so there is one copy shared by all objects and it ends at 3. Each object's `id` is the value of the counter when it was created, so the last object has id 3.

?2 [References] What does this program print?
```java
public class Main {
    static class Box { int v; }
    static void change(Box b) {
        b.v = 99;
        b = new Box();
        b.v = 5;
    }
    public static void main(String[] args) {
        Box x = new Box();
        x.v = 1;
        change(x);
        System.out.println(x.v);
    }
}
```
(a) 1
(b) 5
(c)* 99
(d) 0
=> Java passes the reference by value. `b.v = 99` changes the shared object, so the caller sees 99. The statement `b = new Box()` only re-points the local copy of the reference, so the later `b.v = 5` changes a different object and x is unaffected.

?2 [Strings] What does this program print?
```java
public class Main {
    public static void main(String[] args) {
        String a = "hi";
        String b = "hi";
        String c = new String("hi");
        System.out.println((a == b) + " " + (a == c) + " " + a.equals(c));
    }
}
```
(a) true true true
(b)* true false true
(c) false false true
(d) true false false
=> Literals are interned, so a and b are the same object. `new String("hi")` creates a separate object, so a == c is false, but equals compares the characters and is true.
!py assert printed(stem) == ans.split()

?2 [Constructors] What is the result of compiling and running this program?
```java
public class Main {
    static class A {
        A(int x) { System.out.print("A "); }
    }
    public static void main(String[] args) {
        A a = new A();
    }
}
```
(a) prints A
(b) prints nothing and runs normally
(c)* a compile-time error, because the class has no no-argument constructor
(d) a run-time NullPointerException
=> Once a class declares any constructor, the compiler no longer supplies the default no-argument constructor, so `new A()` does not compile.

?2 [Initialisation order] What does this program print?
```java
public class Main {
    static class Base {
        Base() { System.out.print("Base "); init(); }
        void init() { System.out.print("base-init "); }
    }
    static class Derived extends Base {
        int x = 5;
        Derived() { System.out.print("Derived "); }
        @Override void init() { System.out.print(x + " "); }
    }
    public static void main(String[] args) {
        new Derived();
    }
}
```
(a) Base base-init Derived
(b) Base 5 Derived
(c)* Base 0 Derived
(d) Derived Base 5
=> The parent constructor runs first. It calls the overridden init(), which runs in Derived, but Derived's field initialiser `x = 5` has not run yet, so x still has its default value 0. Calling overridable methods from a constructor is therefore a bug waiting to happen.
!py assert printed(stem) == ans.split()

?2 [Constructor chaining] What does this program print?
```java
public class Main {
    static class A {
        A() { this(5); System.out.print("A() "); }
        A(int x) { System.out.print("A(int) "); }
    }
    public static void main(String[] args) {
        new A();
    }
}
```
(a) A()
(b) A(int)
(c) A() A(int)
(d)* A(int) A()
=> `this(5)` must be the first statement and transfers control to the other constructor, which prints "A(int) " and finishes before the remaining statements of the first constructor run.

?1 [Access control] A member declared protected in a class is accessible
(a) only inside that class
(b) only inside the same package
(c)* inside the same package and in subclasses, even in other packages
(d) from anywhere
=> `protected` includes package access plus access from subclasses in other packages (through inheritance). `private` is class-only and `public` is everywhere.

?2 [Copying] What does this program print?
```java
public class Main {
    public static void main(String[] args) {
        int[] a = {1, 2, 3};
        int[] b = a.clone();
        b[0] = 9;
        int[][] m = {{1}, {2}};
        int[][] n = m.clone();
        n[0][0] = 7;
        System.out.println(a[0] + " " + m[0][0]);
    }
}
```
(a) 9 7
(b) 1 1
(c)* 1 7
(d) 9 1
=> `clone()` on a one-dimensional array of ints copies the elements, so changing b leaves a unchanged. On a two-dimensional array it is a shallow copy: n and m share the same inner arrays, so n[0][0] = 7 also changes m[0][0].
!py assert printed(stem) == ans.split()

?2 [Immutability] What does this program print?
```java
public class Main {
    public static void main(String[] args) {
        String s = "a";
        s.concat("b");
        s += "c";
        System.out.println(s);
    }
}
```
(a) a
(b) ab
(c)* ac
(d) abc
=> Strings are immutable. `s.concat("b")` returns a new string that is thrown away, so s is still "a". `s += "c"` creates a new string "ac" and assigns it to s.
!py assert printed(stem) == ans.split()

?2 [Encapsulation] What does this program print?
```java
import java.util.*;

public class Main {
    public static void main(String[] args) {
        List<String> inner = new ArrayList<>(List.of("a"));
        List<String> view = Collections.unmodifiableList(inner);
        inner.add("b");
        System.out.println(view.size());
    }
}
```
(a) 1
(b)* 2
(c) 0
(d) it throws an exception
=> `unmodifiableList` is a read-only **view**, not a copy: it cannot be changed through the view, but it reflects changes to the underlying list. To make a snapshot use `List.copyOf(inner)`.
!py assert printed(stem) == ans.split()

?2 [Final] What does this program print?
```java
import java.util.*;

public class Main {
    public static void main(String[] args) {
        final List<Integer> list = new ArrayList<>();
        list.add(1);
        System.out.println(list);
    }
}
```
(a) a compile-time error, because list is final
(b) []
(c)* [1]
(d) an UnsupportedOperationException
=> `final` makes the reference constant, not the object. The variable cannot be reassigned, but the list it refers to can still be modified.
!py assert printed(stem) == ["[1]"]

?1 [Records] A Java record declaration such as `record Point(int x, int y) {}` automatically provides
(a) only a constructor
(b) setters for every component
(c)* a constructor, accessors, equals, hashCode and toString
(d) a deep-copy method
=> A record is a transparent immutable data carrier: the compiler generates the canonical constructor, accessor methods (x(), y()), and equals, hashCode and toString based on the components. There are no setters.

?1 [Equality] If two objects are equal according to equals(), the hashCode contract requires that
(a) their hash codes are different
(b)* their hash codes are the same
(c) they are the same object
(d) they are in the same package
=> Equal objects must return equal hash codes. The converse is not required: two unequal objects may share a hash code (a collision).

?1 [Abstraction] Which statement best distinguishes abstraction from encapsulation?
(a) abstraction hides fields; encapsulation hides classes
(b)* abstraction exposes only the essential operations and hides complexity; encapsulation protects state by restricting access to it
(c) they are two names for the same idea
(d) abstraction is only possible with inheritance
=> Abstraction is about presenting a simple interface that hides how things work, usually through interfaces or abstract classes. Encapsulation is about controlling access to the data so invariants hold. They support each other.
