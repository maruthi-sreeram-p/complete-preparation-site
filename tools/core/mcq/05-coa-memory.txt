# Computer Organisation Part 5, the memory hierarchy: original questions. Format: see tools/build_gate.py

?2 [Memory chips] A memory of 64K × 16 bits is built from 16K × 4 bit chips. The number of chips required is
(a) 4
(b) 8
(c)* 16
(d) 32
=> Width: 16 / 4 = 4 chips side by side. Depth: 64K / 16K = 4 rows. Total 4 × 4 = 16 chips, with the 2 high address bits selecting the row through a decoder.
!py assert num(ans) == (64 // 16) * (16 // 4)

?2 [Cache fields] A 32-bit address is used with a 16 KB direct-mapped cache with 16-byte blocks. The number of tag bits is
(a) 14
(b) 16
(c)* 18
(d) 22
=> Offset = log₂ 16 = 4 bits. Blocks = 16 KB / 16 B = 1024, so index = 10 bits. Tag = 32 − 10 − 4 = 18 bits.
!py assert cache_fields(32, 16 * 1024, 16, 1) == (num(ans), 10, 4)

?2 [Cache fields] A 32-bit address is used with a 32 KB 4-way set-associative cache with 64-byte blocks. The number of tag bits is
(a) 17
(b)* 19
(c) 21
(d) 26
=> Offset = 6 bits. Blocks = 32 KB / 64 B = 512 and sets = 512 / 4 = 128, so index = 7 bits. Tag = 32 − 7 − 6 = 19 bits.
!py assert cache_fields(32, 32 * 1024, 64, 4)[0] == num(ans)

?2 [Cache fields] A cache has 512 blocks. It is direct-mapped with a 17-bit tag, and each block also keeps one valid bit. The total size of the tag and valid-bit storage in bytes is
(a) 1,088
(b)* 1,152
(c) 1,024
(d) 1,216
=> Each block needs 17 + 1 = 18 bits, so the store holds 512 × 18 = 9,216 bits = 1,152 bytes.
!py assert num(ans) == 512 * (17 + 1) // 8

?2 [Conflict misses] The block numbers 0, 4, 8, 0, 4, 8, 16, 0, 4 are accessed in order in a direct-mapped cache with 4 lines (initially empty). The number of misses is
(a) 4
(b) 6
(c) 8
(d)* 9
=> Blocks 0, 4, 8 and 16 all map to line 0 (block mod 4 = 0), so each access evicts the previous block and every one of the 9 accesses misses.
!py assert cache_misses([0, 4, 8, 0, 4, 8, 16, 0, 4], 4, 1) == num(ans)

?2 [Associativity] The same access sequence 0, 4, 8, 0, 4, 8, 16, 0, 4 runs in a fully associative cache with 4 lines and LRU replacement. The number of misses is
(a)* 4
(b) 5
(c) 7
(d) 9
=> Only four different blocks (0, 4, 8, 16) are used, and four lines can hold them all: the 4 compulsory misses are the only ones. Full associativity removes the conflict misses of the direct-mapped cache.
!py assert cache_misses([0, 4, 8, 0, 4, 8, 16, 0, 4], 1, 4) == num(ans)

?2 [AMAT] A cache has a hit time of 2 ns, a miss rate of 4% and a miss penalty of 80 ns. The average memory access time in ns is
(a) 3.2
(b)* 5.2
(c) 5.0
(d) 82
=> AMAT = hit time + miss rate × miss penalty = 2 + 0.04 × 80 = 5.2 ns.
!py assert abs(amat(2, 0.04, 80) - num(ans)) < 1e-9

?2 [AMAT] An L1 cache has a 1 ns hit time and a 10% local miss rate. The L2 cache has a 10 ns hit time and a 20% local miss rate. Main memory takes 100 ns. The average memory access time in ns is
(a) 3
(b)* 4
(c) 5
(d) 7
=> AMAT = 1 + 0.1 × (10 + 0.2 × 100) = 1 + 0.1 × 30 = 4 ns.
!py assert abs(amat_two_level(1, 0.1, 10, 0.2, 100) - num(ans)) < 1e-9

?2 [CPI] A processor has a base CPI of 1.2. Each instruction makes 1 instruction fetch and, on average, 0.3 data accesses. The cache miss rate is 2% and the miss penalty is 50 cycles. The effective CPI is
(a) 1.5
(b) 2.2
(c)* 2.5
(d) 3.0
=> Memory stall cycles per instruction = 1.3 × 0.02 × 50 = 1.3, so CPI = 1.2 + 1.3 = 2.5.
!py assert abs(1.2 + 1.3 * 0.02 * 50 - num(ans)) < 1e-9

?1 [Write policy] In a write-back cache, the dirty bit of a block is used to
(a) mark a block that has never been accessed
(b) record that the block was read more than once
(c)* record that the block was modified and must be written to memory on eviction
(d) choose which block to replace under LRU
=> A write-back cache updates only the cache on a write and sets the dirty bit. When the block is evicted, it is written back to memory only if the bit is set.

?1 [Miss types] A miss that occurs on the very first access to a block is a
(a)* compulsory miss
(b) capacity miss
(c) conflict miss
(d) coherence miss
=> The block has never been in the cache, so the miss is unavoidable (compulsory, or cold). Capacity misses occur when the working set exceeds the cache, and conflict misses when blocks compete for the same set.

?1 [Cache design] Which change most directly reduces conflict misses?
(a) increasing the block size
(b)* increasing the associativity
(c) using write-through instead of write-back
(d) decreasing the clock rate
=> Conflict misses occur because blocks that map to the same set evict each other. More ways per set let those blocks coexist.

?2 [Virtual memory] A system has 32-bit virtual addresses, 8 KB pages and 4-byte page table entries. The size of a single-level page table for one process is
(a) 1 MB
(b)* 2 MB
(c) 4 MB
(d) 8 MB
=> 8 KB = 2¹³, so the page number has 32 − 13 = 19 bits and there are 2¹⁹ entries. Table size = 2¹⁹ × 4 B = 2 MB.
!py assert num(ans) == 2 ** (32 - 13) * 4 / 2 ** 20

?2 [TLB] The TLB hit ratio is 80%, a TLB lookup takes 5 ns and a memory access takes 50 ns. A single-level page table is used. The effective memory access time in ns is
(a) 55
(b)* 65
(c) 70
(d) 105
=> Hit: 5 + 50 = 55 ns. Miss: 5 + 50 (page table) + 50 (data) = 105 ns. EAT = 0.8 × 55 + 0.2 × 105 = 44 + 21 = 65 ns.
!py assert abs(0.8 * (5 + 50) + 0.2 * (5 + 50 + 50) - num(ans)) < 1e-9

?2 [Page replacement] A process uses 3 frames with FIFO replacement and references the pages 1,2,3,4,1,2,5,1,2,3,4,5. The number of page faults with 4 frames instead is
(a) 6
(b) 8
(c)* 10
(d) 12
=> With 3 frames FIFO faults 9 times; with 4 frames it faults 10 times. More frames giving more faults is Belady's anomaly, which affects FIFO but not LRU or the optimal policy.
!py refs = [1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5]
!py assert page_faults(refs, 3, "FIFO") == 9 and page_faults(refs, 4, "FIFO") == num(ans)

?2 [Page replacement] For the reference string 7,0,1,2,0,3,0,4,2,3,0,3,2 and 3 frames, the optimal replacement policy causes how many page faults?
(a) 6
(b)* 7
(c) 9
(d) 10
=> The optimal policy evicts the page whose next use is farthest in the future. Simulating the string gives 7 faults, against 9 for LRU and 10 for FIFO.
!py refs = [7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2]
!py assert page_faults(refs, 3, "OPT") == num(ans) == 7 and page_faults(refs, 3, "LRU") == 9 and page_faults(refs, 3, "FIFO") == 10

?2 [Page faults] Memory access takes 100 ns and servicing a page fault takes 8 ms. To keep the effective access time within 10% of 100 ns, the page-fault rate must be below about
(a) 1.25 × 10⁻⁴
(b) 1.25 × 10⁻⁵
(c)* 1.25 × 10⁻⁶
(d) 1.25 × 10⁻⁷
=> EAT = 100 + p × (8,000,000 − 100) ns must be at most 110 ns, so p ≤ 10 / 7,999,900 ≈ 1.25 × 10⁻⁶: fewer than one fault per 800,000 accesses.
!py assert abs(10 / (8_000_000 - 100) - 1.25e-6) < 1e-9 and "⁻⁶" in ans

?1 [Memory technology] Compared with SRAM, DRAM
(a) is faster and more expensive per bit
(b)* is cheaper per bit and needs periodic refresh
(c) needs no refresh because it uses flip-flops
(d) is used for CPU registers
=> A DRAM cell is one transistor and one capacitor, so it is dense and cheap but its charge leaks and must be refreshed. SRAM cells are flip-flops: faster, larger and costlier, used for caches.
