# Computer Organisation Part 6, I/O, buses and storage: original questions. Format: see tools/build_gate.py

?2 [Buses] A system bus has a 64-bit data path and performs one transfer per clock cycle at 100 MHz. Its peak bandwidth is
(a) 80 MB/s
(b) 400 MB/s
(c)* 800 MB/s
(d) 6,400 MB/s
=> Each transfer moves 64 bits = 8 bytes and there are 100 × 10⁶ transfers per second: 8 × 100 × 10⁶ = 800 MB/s.
!py assert num(ans) == 8 * 100

?2 [Buses] A processor has 36 address lines and uses byte-addressable memory. The maximum memory it can address, in GiB, is
(a) 16
(b) 32
(c)* 64
(d) 128
=> 2³⁶ bytes = 2⁶ × 2³⁰ = 64 GiB.
!py assert num(ans) == 2 ** 36 // 2 ** 30

?1 [I/O addressing] In memory-mapped I/O
(a)* device registers are accessed with ordinary load and store instructions
(b) devices use a separate address space accessed with IN and OUT instructions
(c) devices can only be accessed through DMA
(d) the CPU needs no address bus to reach devices
=> Memory-mapped I/O assigns device registers addresses in the normal memory address space, so no special I/O instructions are needed. Isolated (port-mapped) I/O uses a separate space with IN and OUT.

?1 [Arbitration] In daisy-chain bus arbitration, priority is decided by
(a) a central arbiter with a priority table
(b) a random choice
(c)* the position of the device along the chain: the one nearest the arbiter wins
(d) the devices negotiating among themselves
=> The grant signal travels along the chain, so the device closest to the arbiter sees it first. Devices at the end of the chain may starve.

?2 [Interrupts vs DMA] A device delivers data at 2,000,000 bytes per second in 4-byte words and interrupts the CPU once per word. Each interrupt service routine takes 600 cycles on a 1.5 GHz CPU. The fraction of CPU time spent in the ISR is
(a) 2%
(b) 10%
(c)* 20%
(d) 40%
=> 2,000,000 / 4 = 500,000 interrupts per second, each costing 600 cycles: 3 × 10⁸ cycles per second out of 1.5 × 10⁹ = 20%.
!py assert abs(500_000 * 600 / 1.5e9 * 100 - num(ans)) < 1e-9

?2 [Interrupts vs DMA] The same device now uses DMA with 4,000-byte blocks and one interrupt per block, each interrupt costing 3,000 cycles on the 1.5 GHz CPU. The fraction of CPU time spent servicing interrupts is
(a)* 0.1%
(b) 1%
(c) 5%
(d) 20%
=> 2,000,000 / 4,000 = 500 interrupts per second, each costing 3,000 cycles: 1.5 × 10⁶ cycles per second out of 1.5 × 10⁹ = 0.1%.
!py assert abs(500 * 3000 / 1.5e9 * 100 - num(ans)) < 1e-9

?1 [Interrupts] When the CPU accepts an interrupt, the minimum state it must save automatically so that the interrupted program can resume is
(a) the contents of all memory
(b)* the program counter and the status flags
(c) only the stack pointer
(d) nothing, because the ISR always restarts the program
=> To resume correctly the CPU must remember where it was (the PC) and the condition flags; the ISR saves any other registers it uses. A return-from-interrupt instruction restores them.

?1 [Interrupts] Which of the following is raised by the CPU itself during the execution of an instruction rather than by an external device?
(a) a keyboard interrupt
(b) a disk completion interrupt
(c)* a divide-by-zero exception
(d) a timer interrupt
=> Exceptions (traps) such as divide by zero, page faults and system calls arise from the executing instruction. Keyboard, disk and timer interrupts come from outside the CPU.

?2 [Disks] The average rotational latency of a 10,000 rpm disk in milliseconds is
(a) 1.5
(b)* 3
(c) 6
(d) 8.3
=> One rotation takes 60,000 / 10,000 = 6 ms. On average the wanted sector is half a rotation away: 3 ms.
!py assert num(ans) == 0.5 * 60000 / 10000

?2 [Disks] A 7,200 rpm disk has an average seek time of 4 ms, 512-byte sectors and 200 sectors per track. The average time to read one 4 KB block (8 consecutive sectors on one track) is closest to
(a)* 8.5 ms
(b) 12.3 ms
(c) 4.5 ms
(d) 16.7 ms
=> Average rotational latency = ½ × 8.33 ms = 4.17 ms. Transfer = 8/200 × 8.33 ms = 0.33 ms. Total = 4 + 4.17 + 0.33 ≈ 8.5 ms.
!py assert abs(disk_access_ms(7200, 4, 512, 200, 4096) - num(ans)) < 0.05

?2 [RAID] Eight 4 TB disks are configured as RAID 5. The usable capacity in TB is
(a) 16
(b) 24
(c)* 28
(d) 32
=> RAID 5 stores one disk's worth of parity spread over the array, so usable capacity is (8 − 1) × 4 = 28 TB.
!py assert num(ans) == raid_usable(5, 8, 4)

?2 [RAID] Six 2 TB disks are configured as RAID 10 (a stripe of mirrored pairs). The usable capacity in TB is
(a) 4
(b)* 6
(c) 8
(d) 10
=> RAID 10 mirrors every disk, so half of the raw capacity is usable: 6 × 2 / 2 = 6 TB.
!py assert num(ans) == raid_usable(10, 6, 2)

?2 [RAID] A RAID 5 stripe holds the data blocks D1 = 1011, D2 = 0110, D3 = 1100 and the parity block P = D1 ⊕ D2 ⊕ D3. The disk holding D2 fails. The reconstructed D2 is
(a) 1001
(b)* 0110
(c) 0001
(d) 1111
=> P = 1011 ⊕ 0110 ⊕ 1100 = 0001. The lost block is the XOR of everything that remains: D2 = P ⊕ D1 ⊕ D3 = 0001 ⊕ 1011 ⊕ 1100 = 0110.
!py p = 0b1011 ^ 0b0110 ^ 0b1100
!py assert format(p ^ 0b1011 ^ 0b1100, "04b") == ans

?1 [RAID] RAID 6 differs from RAID 5 in that it
(a) uses mirroring instead of parity
(b)* keeps two independent parity blocks per stripe and survives two simultaneous disk failures
(c) has no redundancy but faster reads
(d) needs only two disks
=> RAID 6 stores two different parity blocks per stripe, giving usable capacity (N − 2) × C and tolerance for any two disk failures, at the cost of more write overhead.

?1 [SSD] In a NAND flash SSD, data is
(a) erased one page at a time and written one block at a time
(b)* written in pages but erased only in larger blocks, so a page cannot be overwritten in place
(c) overwritten in place like a hard disk sector
(d) stored on spinning platters
=> Flash can be programmed page by page but must be erased block by block before it can be written again. The controller therefore remaps writes, wear-levels and garbage-collects; TRIM tells it which blocks are free.
