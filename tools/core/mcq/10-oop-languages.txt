?2 [Initialisation order] What does this program print?
```java
public class Main {
    static class A {
        static { System.out.print("A-static "); }
        A() { System.out.print("A() "); }
    }
    static class B extends A {
        static { System.out.print("B-static "); }
        B() { System.out.print("B() "); }
    }
    public static void main(String[] args) {
        new B();
        new B();
    }
}
```
(a) A-static B-static A() B() A-static B-static A() B()
(b)* A-static B-static A() B() A() B()
(c) A() B() A() B() A-static B-static
(d) B-static A-static B() A()
=> Static initialisers run once, when the class is first initialised, and a parent is initialised before its child. Constructors run for every object, parent first, so the second `new B()` prints only "A() B()".

?2 [try-finally] What does this program print?
```java
public class Main {
    static int f() {
        try {
            return 1;
        } finally {
            System.out.print("finally ");
        }
    }
    public static void main(String[] args) {
        System.out.println(f());
    }
}
```
(a) 1
(b) finally
(c)* finally 1
(d) 1 finally
=> The return value 1 is computed, then the finally block runs (printing "finally "), and only then does the method return, so main prints 1 afterwards.

?2 [Overload resolution] What does this program print?
```java
public class Main {
    static String g(Object o)  { return "Object"; }
    static String g(Integer i) { return "Integer"; }
    static String g(long l)    { return "long"; }
    public static void main(String[] args) {
        System.out.println(g(5));
    }
}
```
(a) Object
(b) Integer
(c)* long
(d) it does not compile because the call is ambiguous
=> The argument 5 is an int. Overload resolution tries, in order: exact match or widening primitive conversion (int to long), then boxing (Integer), then boxing with widening reference conversion (Object). The first phase finds g(long).
!py assert printed(stem) == ans.split()

?2 [Integer cache] What does this program print?
```java
public class Main {
    public static void main(String[] args) {
        Integer a = 127, b = 127, c = 128, d = 128;
        System.out.println((a == b) + " " + (c == d) + " " + c.equals(d));
    }
}
```
(a) true true true
(b)* true false true
(c) false false true
(d) true true false
=> `Integer.valueOf` caches values from −128 to 127, so a and b are the same object. 128 is outside the cache, so c and d are two different objects, but `equals` compares the values.

?2 [Strings] What does this program print?
```java
public class Main {
    public static void main(String[] args) {
        System.out.println(1 + 2 + "a" + 1 + 2);
    }
}
```
(a) 12a12
(b) 3a3
(c)* 3a12
(d) 1a12
=> Evaluation goes left to right: 1 + 2 is integer addition giving 3, then + "a" starts string concatenation ("3a"), and the remaining 1 and 2 are appended as text: "3a12".

?2 [Static context] What is the result of compiling this code?
```java
public class Main {

    public static void main(String[] args) {
        inc();
    }
}
```
(a) it compiles and runs
(b)* a compile-time error: a non-static method cannot be called from a static context

?2 [Python] What does this program print?
```python
def add(item, bucket=[]):
    bucket.append(item)
    return bucket

print(add(1), add(2))
```
(a) [1] [2]
(b)* [1, 2] [1, 2]
(c) [1, 2] [2]
(d) it raises an error
=> The default list is created once, when the function is defined, and shared by every call that does not pass its own. Both calls append to the same list, and both results refer to it. Use `None` as the default and create the list inside the function.

?2 [Python] What does this program print?
```python
class C:
    items = []

a = C()
b = C()
a.items.append(1)
print(b.items)
```
(a) []
(b)* [1]
(c) an AttributeError
(d) None
=> `items` is a class attribute, so a and b share the same list. Appending through `a` changes the shared object. Assigning `a.items = []` instead would create a separate instance attribute.

?2 [Python] What does this program print?
```python
class A:
    def f(self): return "A"
class B(A):
    def f(self): return "B" + super().f()
class C(A):
    def f(self): return "C" + super().f()
class D(B, C):
    pass

print(D().f())
```
(a) BA
(b) BAC
(c)* BCA
(d) DBCA
=> The method resolution order of D is D, B, C, A. `super()` in B calls the next class in D's MRO, which is C (not A), and C's `super()` then reaches A, giving "B" + "C" + "A". Each class is visited once, which solves the diamond problem.
!py assert run_python(code_in(stem, "python")).split() == ans.split()

?2 [Python] What does this program print?
```python
class P:
    def __init__(self, x):
        self.x = x
    def __eq__(self, other):
        return self.x == other.x

try:
    print(len({P(1), P(1)}))
except TypeError:
    print("unhashable")
```
(a) 1
(b) 2
(c)* unhashable
(d) 0
=> A class that defines `__eq__` without `__hash__` gets `__hash__` set to None, so its instances are unhashable and cannot go in a set. Defining both (consistently) fixes it, just as in Java's equals and hashCode contract.

?2 [Python] What does this program print?
```python
class Account:
    def __init__(self, b):
        self._b = b
    @property
    def balance(self):
        return self._b

a = Account(10)
try:
    a.balance = 99
except AttributeError:
    print("read-only")
print(a.balance)
```
(a) 99
(b) read-only 99
(c)* read-only 10
(d) 10
=> A property defined with only a getter is read-only. Assigning to it raises AttributeError, which is caught, and the stored value is unchanged.

?1 [C++] In C++, deleting an object of a derived class through a pointer to a base class whose destructor is not virtual results in
(a) a compile-time error
(b) the derived destructor running normally
(c)* undefined behaviour, typically skipping the derived class's destructor
(d) a Java-style garbage collection
=> Without a virtual destructor the call is bound statically to the base destructor, so the derived part is not cleaned up properly. Classes meant to be used polymorphically need a virtual destructor.

?1 [C++] Object slicing occurs when
(a)* a derived object is copied into a base-class variable by value, losing the derived part
(b) a class has too many virtual functions
(c) an array is partially initialised
(d) a pointer is cast to void*
=> Copying a Derived into a Base variable by value copies only the Base subobject, so the extra data and the overridden behaviour of Derived are lost. Passing by pointer or reference avoids it.

?1 [Generics] A key difference between Java generics and C++ templates is that
(a)* Java erases type arguments at run time, while C++ generates separate code for each instantiation
(b) Java generics are faster than templates
(c) C++ templates are checked only at run time
(d) Java generics can be used with primitive types directly
=> Java generics use type erasure: a `List<String>` and a `List<Integer>` are the same class at run time, which is why you cannot create `new T()`. C++ templates are instantiated per type at compile time. Java generics cannot hold primitives directly (use `Integer`).

(a) write the class definitions immediately

=> Clarifying requirements and scope prevents designing the wrong thing. Entities (nouns) and actions (verbs) then give candidate classes and methods; patterns are applied only where they solve a real problem.
