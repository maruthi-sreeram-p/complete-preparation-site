?1 [Encoding, hashing, encryption] The string dXNlcjpwYXNz is found in a code review as "protected" credentials. It is most likely
(a) AES-encrypted data
(b) a SHA-256 hash
(c)* Base64 encoding, which anyone can reverse
(d) an RSA signature
=> Base64 uses only letters, digits, + and / and is decoded without a key. This one decodes to user:pass. Encoding is not protection.
!py assert b64d('dXNlcjpwYXNz') == 'user:pass'

?1 [Encoding, hashing, encryption] Which statement is true?
(a) hashing can be reversed with the right key
(b)* encryption is reversible with the key, hashing is one-way
(c) Base64 needs a secret key
(d) encoding and encryption are the same
=> Encryption is designed to be undone by the key holder. A hash has no key to undo it. Encoding has no secret at all.

?1 [Encoding, hashing, encryption] HTTP Basic authentication sends credentials as

(d) a signed cookie
=> It is only encoding, so Basic authentication must always run over HTTPS.

?1 [Hash functions] Which hash function is currently considered unsuitable for security because practical collisions exist?
(a) SHA-256
(b)* MD5 (and SHA-1)
(c) SHA-512
(d) SHA3-256
=> MD5 collisions have been practical for years and SHA-1 collisions were shown in 2017. Use SHA-256 or SHA-3.

?1 [Hash functions] Changing one character of a file produces a completely different hash. This is called
(a) salting
(b) key stretching
(c)* the avalanche effect
(d) forward secrecy
=> Small input changes flip about half the output bits, so similar inputs cannot be recognised from their hashes.
!py assert digest('sha256', 'abc') != digest('sha256', 'abd')

?1 [Hash functions] The birthday bound says that finding a collision in an n-bit hash takes about
(a) 2^n attempts
(b)* 2^(n/2) attempts
(c) n² attempts
(d) n attempts
=> A 128-bit hash offers only about 64 bits of collision resistance, which is one reason 128-bit hashes are considered weak for signatures.

?2 [Hash functions] A software vendor publishes an installer and its SHA-256 hash on the same web page. Why is that weaker than it seems?
(a) SHA-256 is broken
(b)* an attacker who can change the download can change the hash on the same page too
(c) hashes cannot detect changes
(d) the hash is too long
=> Integrity checks need a trusted channel for the hash or a digital signature. Otherwise the hash only catches accidental corruption.

?1 [HMAC] HMAC differs from a plain hash because it
(a) is reversible
(b)* mixes in a secret key, so only key holders can produce or verify the tag
(c) is always shorter
(d) encrypts the message
=> A plain hash can be computed by anyone. An HMAC proves integrity and authenticity to someone who shares the key.

?2 [HMAC] An API signs requests with HMAC-SHA256 using a shared secret. The server compares the received signature with the expected one using ==. What is the weakness?
(a) HMAC cannot be used for APIs
(b)* a normal comparison can leak timing information, so a constant-time comparison should be used
(c) the signature is too long
(d) the secret must be public
=> Early-exit comparisons take slightly longer the more leading bytes match, letting an attacker recover a valid tag byte by byte. Use a constant-time compare such as MessageDigest.isEqual.

?2 [HMAC] Two parties share the key "k". The HMAC-SHA256 of the message "pay 100" is computed by both. If an attacker changes the message to "pay 900" without the key, the receiver will
(a)* see that the tag does not match
(b) still accept it
(c) decrypt it
(d) see the same tag
=> The tag depends on the message and the key, so a modified message produces a different tag that the attacker cannot recompute.
!py assert hmac_hex('k', 'pay 100') != hmac_hex('k', 'pay 900')

?1 [Symmetric encryption] The block size of AES is
(a) 64 bits
(b)* 128 bits
(c) 256 bits regardless of the key
(d) the same as the key size
=> AES always works on 128-bit blocks. The key can be 128, 192 or 256 bits.

?1 [Symmetric encryption] Which AES key length is NOT valid?
(a) 128 bits
(b) 192 bits
(c) 256 bits
(d)* 512 bits
=> AES defines 128, 192 and 256-bit keys. 512 bits is a hash size and not an AES key size.

?1 [Symmetric encryption] Which of these ciphers should no longer be used?
(a) AES-256
(b) ChaCha20-Poly1305
(c)* DES
(d) AES-128-GCM
=> DES has a 56-bit key and can be brute-forced. 3DES is deprecated as well.

?1 [Symmetric encryption] The major weakness of ECB mode is that
(a) it is too slow
(b)* identical plaintext blocks give identical ciphertext blocks, leaking patterns
(c) it needs a 4096-bit key
(d) it cannot decrypt
=> Structure in the data, such as an image, remains visible in the ciphertext.

?1 [Symmetric encryption] AES-GCM is called an AEAD mode because it
(a) is asymmetric
(b)* provides confidentiality and integrity together, via an authentication tag
(c) uses a public key
(d) works without a nonce
=> AEAD means authenticated encryption with associated data. Tampering is detected when decrypting.

?2 [Symmetric encryption] A developer encrypts every message with AES-GCM using the same key and a fixed all-zero nonce. What is the problem?
(a) none, the key is secret
(b)* reusing a nonce under one key breaks the confidentiality and authenticity guarantees of GCM
(c) AES-GCM does not use nonces
(d) the messages become longer
=> GCM requires a unique nonce for every encryption with the same key. Generate a fresh random 96-bit nonce or use a counter.

?2 [Symmetric encryption] An encrypted cookie uses AES-CBC with no MAC. An attacker flips bits in the ciphertext and the server accepts it, with the decrypted value altered. Which property is missing?
(a) confidentiality
(b)* integrity (authenticated encryption)
(c) availability
(d) forward secrecy
=> CBC alone does not detect modification. Use AES-GCM or encrypt-then-MAC.

?1 [Symmetric encryption] Which Java class should be used to generate keys, nonces and tokens?
(a) java.util.Random
(b) Math.random()
(c)* java.security.SecureRandom
(d) System.currentTimeMillis()
=> Random and Math.random are predictable. SecureRandom draws from the operating system's entropy source.

?2 [Symmetric encryption] A one-time pad XOR operation: the byte 0x5A is XORed with the key byte 0x3C. The result is
(a) 0x96
(b)* 0x66
(c) 0x7E
(d) 0x00

?1 [Classical ciphers] A Caesar cipher with shift 3 turns KHOOR back into
(a) KHOOR
(b) EBIIL
(c)* HELLO
(d) NKRRU
=> Each letter moves three places back: K→H, H→E, O→L, O→L, R→O. A Caesar cipher has only 25 useful keys and is trivial to brute-force.
!py assert caesar('KHOOR', -3) == ans

?1 [Classical ciphers] Why can a Caesar cipher not be considered secure?
(a) it uses a public key
(b)* the key space is tiny, so every shift can be tried in a moment
(c) it uses a hash
(d) it needs a certificate
=> There are only 25 non-trivial shifts. Even a substitution cipher falls to letter-frequency analysis.

?1 [Public-key cryptography] To send a confidential message to Bob using public-key encryption, Alice encrypts with
(a) Alice's private key
(b)* Bob's public key
(c) Alice's public key
(d) Bob's private key

?1 [Public-key cryptography] To create a digital signature, the signer uses
(a)* their private key
(b) the recipient's public key

(d) the recipient's private key

?1 [Public-key cryptography] A digital signature does NOT by itself provide
(a) integrity
(b) authenticity
(c) non-repudiation
(d)* confidentiality of the message

?1 [Public-key cryptography] 256-bit elliptic-curve keys give roughly the security of an RSA key of
(a) 256 bits
(b) 1024 bits
(c)* 3072 bits
(d) 512 bits

?2 [Public-key cryptography] Textbook RSA with p = 61, q = 53 and public exponent e = 17. The private exponent d is
(a) 17
(b) 3120

(b) 3233

?2 [Public-key cryptography] In a Diffie-Hellman exchange with p = 23, g = 5, Alice's secret a = 6 and Bob's secret b = 15, the shared secret is
(a) 8
(b) 19
(c)* 2
(d) 15
=> Alice sends 5^6 mod 23 = 8 and Bob sends 5^15 mod 23 = 19. Alice computes 19^6 mod 23 = 2 and Bob computes 8^15 mod 23 = 2.
!py assert dh_shared(23, 5, 6, 15)[2] == num(ans)

?2 [Public-key cryptography] Plain Diffie-Hellman between two strangers is still vulnerable to
(a) brute force of small keys only

(c) hash collisions
(d) nothing, it is perfectly secure
=> An active attacker can run one exchange with each party. Certificates or signatures are needed to authenticate the public values.

?1 [Public-key cryptography] Why do real systems encrypt bulk data with a symmetric cipher and not with RSA?
(a) RSA cannot encrypt anything

(d) RSA is not secure

?1 [TLS] Forward secrecy means
(a) the server's certificate never expires
(b)* stealing the server's long-term private key later does not reveal past recorded sessions
(c) the browser caches the key
(d) data is compressed
=> Each session uses fresh ephemeral Diffie-Hellman keys that are discarded afterwards. TLS 1.3 requires this.

?1 [TLS] Which protocol versions should be disabled on a modern server?
(a) TLS 1.2 and 1.3
(b) TLS 1.3 only
(c)* SSL 3.0, TLS 1.0 and TLS 1.1
(d) none, compatibility matters most
=> Older versions have known weaknesses (POODLE, BEAST) and are deprecated. Use TLS 1.2 or 1.3.

?1 [TLS] A TLS certificate binds

?2 [TLS] A browser shows a certificate warning for shop.example.com. The certificate is valid and trusted, but it was issued for www.example.org. The problem is

?1 [TLS] Mutual TLS (mTLS) means

?1 [Password storage] Which is the right way to store a user's password?
(a) encrypted with AES, key in the code
(b) SHA-256 without a salt
(c)* a salted hash made with a slow algorithm such as Argon2id, bcrypt or PBKDF2
(d) Base64
=> Encryption is reversible if the key leaks, and a fast unsalted hash is cracked at billions of guesses per second.

?1 [Password storage] A salt is

?1 [Password storage] Why are rainbow tables ineffective against salted hashes?
(a)* the table would have to be rebuilt for every salt
(b) salts are encrypted
(c) hashes are reversible
(d) salts are public keys
=> A precomputed table only works for one hash function without salt. A unique salt per user forces separate work for each hash.

?1 [Password storage] The cost factor of bcrypt is increased from 10 to 12. The work per hash becomes
(a) 2 times higher
(b)* 4 times higher
(c) 12 times higher
(d) unchanged
=> The work is 2^cost, so cost 12 is 2^12 / 2^10 = 4 times more.
!py assert 2 ** 12 // 2 ** 10 == num(ans.split()[0])

?2 [Password storage] A breach exposes a table of unsalted SHA-1 password hashes. Which attack is now fastest?

(c) breaking AES
(d) phishing the CEO
=> Unsalted fast hashes of common passwords are in public lookup tables. The company should force resets and move to a salted slow hash.

?2 [Java crypto] A developer writes `MessageDigest.getInstance("SHA-256").digest(password.getBytes())` to store a password. What is wrong?

=> A password hash must be slow and salted. SHA-256 alone is designed to be fast.

?2 [Java crypto] A repository contains `private static final String KEY = "my-secret-key-123";` used for AES encryption. The main issue is
