# Ethical hacking labs and methodology: 50 original questions. Format: see tools/build_gate.py (?1 recall, ?2 scenario)

?1 [Methodology] A penetration test differs from a vulnerability assessment because it
(a) uses no tools
(b)* goes further by safely exploiting weaknesses within an agreed scope to show impact
(c) is always automated
(d) ignores scope
=> A vulnerability assessment lists weaknesses. A pentest demonstrates which ones can actually be abused.

?1 [Methodology] In a grey-box web test the tester usually has
(a) no information at all
(b)* partial knowledge, such as one or more normal user accounts
(c) the full source code and design
(d) administrator rights on the server
=> Grey box is the most common web test, because authorisation bugs need logged-in identities.

?1 [Methodology] A purple team exercise is
(a) a team of auditors
(b)* red and blue teams cooperating so attacks directly improve detections
(c) a marketing event
(d) a type of malware
=> Each simulated technique is checked against monitoring, and gaps are fixed on the spot.

?1 [Methodology] Which document gives a tester legal permission and defines what may be tested?
(a) the network diagram
(b) a CV
(c)* the signed scope and rules-of-engagement agreement
(d) a verbal OK
=> Written authorisation and scope protect both the tester and the client.

?2 [Methodology] During an authorised test of 10.1.1.0/24 you discover a server at 10.1.5.20 that appears vulnerable. You should
(a) test it quickly
(b)* leave it alone and tell the client, because it is outside the agreed scope
(c) scan it silently
(d) shut it down
=> Out of scope means untouched. The client can decide to extend the scope in writing.

?1 [Methodology] The correct order of the early pentest phases is
(a) exploitation, reconnaissance, reporting, scoping
(b)* pre-engagement (scope), reconnaissance, scanning and enumeration, vulnerability analysis, exploitation
(c) reporting, scanning, scope, exploitation
(d) scanning, reporting, scope, reconnaissance
=> You plan and get permission first, learn about the target, then analyse, then prove.

?1 [Methodology] Passive reconnaissance means
(a) scanning ports slowly
(b)* gathering information from public sources without contacting the target systems
(c) logging into servers
(d) guessing passwords
=> Examples: WHOIS, certificate transparency logs, search engines, public code repositories.

?1 [Methodology] The OWASP WSTG is
(a) a scanner
(b)* a free testing guide with a checklist of what to test in a web application
(c) a certificate
(d) a Java library
=> The Web Security Testing Guide organises tests by area such as authentication, authorisation and input validation.

?1 [Methodology] After a client fixes the reported issues, a tester performs a
(a) new exploit
(b)* retest to verify the fixes
(c) social engineering test
(d) takedown
=> Retesting confirms the fixes work and did not introduce a new problem.

?1 [Lab setup] The safest network mode for a lab with deliberately vulnerable VMs is
(a) bridged to your home Wi-Fi
(b)* host-only or internal
(c) directly on the internet
(d) a public cloud subnet
=> Vulnerable machines must not be reachable from other networks.

?1 [Lab setup] Why take VM snapshots before experiments?
(a) to save disk space
(b)* to restore a clean state quickly if something breaks
(c) to hide logs
(d) to encrypt the VM
=> Snapshots make destructive tests and reinstallation cheap.

?1 [Lab setup] Which is a legal practice target for web application security?
(a) your neighbour's Wi-Fi router
(b) your college's website without permission
(c)* OWASP Juice Shop running on your own machine
(d) a bank's login page
=> Deliberately vulnerable applications are designed to be attacked in a controlled setting.

?1 [Lab setup] Which command starts OWASP Juice Shop locally in Docker on port 3000?
(a) docker build juice
(b)* docker run -p 3000:3000 bkimminich/juice-shop
(c) docker stop juice
(d) docker rmi 3000
=> The -p flag maps the container port to your machine, so you can browse to http://localhost:3000.

?1 [Lab setup] Which platform offers free, structured web security labs from the makers of Burp Suite?
(a) Netflix
(b)* PortSwigger Web Security Academy
(c) Stack Overflow
(d) LinkedIn Learning only
=> It covers every common web vulnerability class with interactive labs.

?1 [Lab setup] OverTheWire's Bandit wargame is best for learning
(a) cloud billing
(b)* the Linux command line and basic security concepts
(c) machine learning
(d) UI design
=> It is a good first step before networking and web labs.

?1 [Tools] Burp Suite acts as
(a) a password manager
(b)* an intercepting proxy that lets you inspect, replay and modify HTTP requests
(c) a hypervisor
(d) a firewall
=> It sits between the browser and the application. Repeater resends a request with changes.

?1 [Tools] Which tool is used to see and replay a single modified request in Burp?
(a) Intruder
(b)* Repeater
(c) Comparer
(d) Sequencer
=> Repeater is for manual, iterative testing of one request.

?1 [Tools] OWASP ZAP is
(a) a closed-source scanner only
(b)* a free open-source proxy and scanner that is easy to automate in pipelines
(c) a Linux distribution
(d) a ransomware family
=> It is often used for DAST in CI.

?1 [Tools] ffuf and gobuster are used to
(a) crack passwords
(b)* discover hidden paths and files by trying a wordlist
(c) capture packets
(d) decrypt TLS
=> They are noisy and must only be run against targets you are allowed to test.

?1 [Tools] CyberChef is useful for
(a) cooking recipes
(b)* decoding and transforming data such as Base64, hex, XOR and hashes in a browser
(c) running exploits
(d) scanning ports
=> It chains operations, which makes it handy in CTFs and in analysis.

?1 [Tools] hashcat mode 3200 refers to
(a) MD5
(b) SHA-256
(c)* bcrypt
(d) NTLM
=> Modes: 0 = MD5, 100 = SHA-1, 1400 = SHA-256, 3200 = bcrypt.

?2 [Tools] In a lab you crack an unsalted MD5 hash of a common password in seconds with a wordlist, but the same wordlist makes little progress against bcrypt. What does this show?
(a) MD5 is better for passwords
(b)* fast unsalted hashes are weak for passwords, while slow salted hashes make every guess expensive
(c) wordlists do not work
(d) bcrypt is reversible
=> That is the reason password storage uses Argon2, scrypt, bcrypt or PBKDF2 with salts.

?2 [Tools] Wireshark shows a clear-text POST to /login containing username and password in the body. What does this demonstrate?
(a) the password is hashed
(b)* the application is not using TLS, so anyone on the path can read credentials
(c) the server is fast
(d) the packet is corrupted
=> Enforce HTTPS and HSTS. Never send credentials over plain HTTP.

?1 [Tools] sqlmap automates SQL injection testing. It should be used
(a) on any website
(b)* only on authorised targets or labs, after you understand the manual technique
(c) instead of learning SQL
(d) only on bank sites
=> Automated tools are loud, can damage data and are illegal when used without permission.

?1 [Web testing] Which testing activity finds the most serious bugs in typical web applications?
(a) running only an automated scan
(b)* comparing requests across two users and roles to find access control flaws
(c) counting HTML tags
(d) checking the logo
=> Scanners are poor at authorisation logic. A human must test who can access what.

?1 [Web testing] The first step of testing an unfamiliar web application is to
(a) launch an exploit
(b)* map it by browsing every feature through the proxy, noting endpoints, parameters and roles
(c) run a password cracker
(d) write the report
=> You cannot test what you have not discovered.

?2 [Web testing] A tester changes the request GET /api/orders/77 to /api/orders/78 and receives an order that belongs to another user. The finding is
(a) XSS
(b)* IDOR / broken access control
(c) SQL injection
(d) CSRF
=> The server did not check ownership. Report with the minimum data needed and a clear fix.

?2 [Web testing] A tester sends a single quote in a search parameter and gets a database error message. This suggests
(a) a CSS bug
(b)* possible SQL injection and verbose error disclosure
(c) a missing image
(d) a slow network
=> Unhandled quotes in SQL and visible errors are strong leads. Confirm with careful, harmless probes.

?2 [Web testing] Changing the parameter `?next=/home` to `?next=https://example.org` redirects the user to another site after login. The issue is
(a) clickjacking
(b)* an open redirect
(c) SSRF
(d) CSRF
=> It helps phishing by borrowing the site's trust. Allow only relative paths or allow-listed hosts.

?2 [Web testing] A tester finds that a hidden "Delete user" button works for a normal user if the API call is made manually. The category is
(a) information disclosure
(b)* missing function-level authorisation (broken access control)
(c) XXE
(d) weak TLS
=> The server did not check the role. Hiding the button was not a control.

?2 [Web testing] The tester sees that the password reset link contains the sequence number of the reset request (reset?id=2031). The risk is
(a) none
(b)* predictable tokens allow resetting other people's passwords
(c) slow e-mail
(d) CORS
=> Reset tokens must be random, single-use and expiring.

?1 [Reporting] A good finding includes
(a) only a scanner screenshot
(b)* title, severity, description, reproduction steps, evidence, impact and remediation
(c) only the exploit code
(d) personal opinions about the developers
=> The reader must be able to understand, reproduce and fix the issue.

?1 [Reporting] The executive summary of a pentest report is written for
(a) the attacker
(b)* non-technical decision makers, with overall risk and priorities
(c) the scanner
(d) the firewall
=> Managers decide where to spend effort, so give them clear priorities.

?2 [Reporting] Which statement is the best impact description for an IDOR on invoices?
(a) "The app has a bug."
(b)* "Any logged-in customer can read all other customers' names, addresses and purchases by counting invoice numbers."
(c) "IDOR is in the OWASP Top 10."
(d) "Severity: very high!!!"
=> Good impact statements say who can do what to which data, in business terms.

?2 [Reporting] A tester rates a missing X-Frame-Options header on a static page "Critical". The better practice is to
(a) keep the rating to get attention
(b)* rate it by realistic impact and likelihood, usually Low, and explain why
(c) remove the finding
(d) rate everything Critical
=> Inflated severity destroys trust. Use CVSS plus context.

?1 [CTF and bounty] A CTF "flag" is
(a) a country symbol
(b)* a string of text hidden in a challenge that proves you solved it
(c) a firewall rule
(d) a certificate
=> Typical format: flag{...}. Submit it on the platform to score.

?1 [CTF and bounty] Which is NOT a standard CTF category?
(a) web
(b) forensics
(c) cryptography
(d)* invoice accounting
=> Common categories: web, crypto, forensics, reverse engineering, pwn and miscellaneous.

?1 [CTF and bounty] On a bug bounty platform the most important thing to read before testing is
(a) the leaderboard
(b)* the programme's scope and rules
(c) the reward table only
(d) other researchers' reports
=> Testing outside scope or against the rules can lose your account or create legal risk.

?2 [CTF and bounty] Your report was marked "duplicate" because another researcher reported the same bug earlier. This is
(a) a sign of failure
(b)* normal; learn from it and test less obvious areas, since duplicates are common for beginners
(c) a reason to stop forever
(d) a reason to publish the bug
=> Duplicates are part of the process. Do not publish the vulnerability.

?1 [CTF and bounty] Responsible disclosure means
(a) publishing exploit code at once
(b)* reporting privately and giving the vendor reasonable time to fix before any publication
(c) demanding payment
(d) keeping the bug secret forever
=> It protects users while still ensuring fixes happen.

?1 [Defender labs] Wazuh and Security Onion are used in home labs as
(a) game engines
(b)* free SIEM / monitoring platforms
(c) web browsers
(d) hypervisors
=> Sending lab machine logs to them teaches log collection and detection.

?1 [Defender labs] Sysmon on Windows provides
(a) faster boot
(b)* detailed process, network and file events for detection
(c) disk encryption
(d) antivirus signatures
=> It logs, for example, parent-child process relationships that default Windows logs lack.

?2 [Defender labs] You run an Atomic Red Team test in your lab and no alert appears. The right next step is to
(a) conclude the lab is secure
(b)* write or tune a detection for that technique, then run the test again to confirm the alert fires
(c) delete the logs
(d) disable the test
=> Detection gaps found in a lab are exactly what the exercise is for.

?2 [Defender labs] You analyse a pcap and find hundreds of DNS queries to long random subdomains of one domain. Which technique is the best fit?
(a) phishing
(b)* DNS tunnelling or data exfiltration
(c) SQL injection
(d) clickjacking
=> High volume, long, high-entropy labels under one domain are the usual indicators.

?1 [Portfolio] Which is the strongest beginner portfolio item for an application security role?
(a) a screenshot of a certificate only
(b)* a repository where you break and then fix a small Spring Boot app, with tests and a short write-up
(c) a list of tools you have heard of
(d) a copy of someone else's walkthrough
=> It shows you can find, explain and fix vulnerabilities in code, which is the actual job.

?1 [Portfolio] Why write a short note after every lab?
(a) to waste time
(b)* explaining what the flaw was, how it works and how to fix it reinforces learning and becomes portfolio material
(c) because platforms require it
(d) to publish the solution to cheat
=> Do not publish active challenge solutions where the platform forbids it. Write about concepts.

?1 [Methodology] A "get out of jail" letter in penetration testing is
(a) a legal textbook
(b)* written authorisation that proves the tester was permitted to perform the agreed tests
(c) a bail bond
(d) a type of exploit
=> It identifies the tester, the scope and the dates, and is the first thing to show if the tests are questioned.

?2 [Web testing] A tester has two accounts, a customer and an admin. Which test is the most valuable for finding access control flaws?
(a) a port scan of the host
(b)* send admin-only requests with the customer's session, and replay the customer's object IDs under the other user
(c) test the login page for typos
(d) measure the page load time
=> Authorisation bugs appear when low-privilege identities can reach high-privilege functions or other users' data.

?1 [Tools] Netcat and curl are valuable for testers because
(a) they hide traffic from logs
(b)* they let you talk to any port or HTTP endpoint by hand and see the raw response
(c) they crack passwords
(d) they replace Burp Suite entirely
=> Understanding raw requests builds the intuition that tools build on.

?2 [Reporting] A finding says "Severity: High" but gives no steps, no evidence and no fix. What is the problem?
(a) none
(b)* the reader cannot reproduce, verify or fix it, so it is unlikely to be acted on
(c) it is too short to read
(d) severity should be omitted
=> A report must let a developer reproduce the issue and know what to change.
