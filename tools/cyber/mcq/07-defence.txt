?1 [SOC basics] A Tier 1 SOC analyst's main job is to
(a) write malware
(b)* triage alerts, close false positives and escalate real incidents
(c) design the corporate network

=> Tier 1 watches the queue, decides what is real and hands real incidents to deeper investigation.

?1 [SOC basics] MTTD stands for
(a) mean time to deploy
(b)* mean time to detect
(c) maximum time to disable
(d) managed threat data
=> It measures how long attackers go unnoticed. Shorter is better, as is MTTR (time to respond or recover).

?1 [SOC basics] Why must the clocks of all servers be synchronised (NTP) for incident investigation?
(a) to save battery
(b)* events from different systems can only be ordered into a timeline if their timestamps agree
(c) to speed up logins
(d) to compress logs
=> Without consistent time, correlating a firewall event with a login event is guesswork.

?1 [Logs] Windows Security event ID 4625 means
(a) a successful logon
(b)* a failed logon
(c) a new service installed
(d) the audit log was cleared
=> 4624 is success, 4625 is failure, 7045 is a new service, 1102 is a cleared audit log.

?1 [Logs] Windows Security event ID 1102 (audit log cleared) is suspicious because
(a) it is a normal daily event

?1 [Logs] Event ID 4688 records

=> Process creation logs, with the command line enabled, are one of the best sources for detecting malicious activity.

?2 [Logs] Which sequence in an authentication log most strongly suggests a successful brute force?
(a) one 4624 for each user
(b)* many 4625 events for an account from one IP, followed by a 4624 for the same account from that IP
(c) a 4625 followed by a logoff

=> Failures followed by a success from the same source mean the guess eventually worked.

?2 [Logs] You see `Failed password for root from 198.51.100.7` 400 times, then `Accepted password for root from 198.51.100.7`. The first action is to

(b)* treat the host as compromised: isolate it, preserve evidence and investigate what root did afterwards
(c) restart SSH
(d) delete the log lines
=> A success after a flood of failures means the attacker got in. Containment and evidence come first.

?2 [Logs] A web access log shows a request containing UNION SELECT and a 200 status with a large response size, from user agent sqlmap. What is the most important observation?

(b)* the 200 and large response suggest the injection may have succeeded and data may have been returned
(c) the URL is long
(d) the request was a GET

?1 [SIEM] "Impossible travel" detection raises an alert when

?2 [SIEM] An organisation has an alert rule for "failed logins > 3 in 10 minutes" and receives 500 alerts a day, mostly users who mistyped passwords. The best improvement is
(a) switch the SIEM off

=> Alert fatigue hides real attacks. Better rules and automation raise the signal-to-noise ratio.

?1 [Alert quality] A real attack that produces no alert is a
(a) true positive
(b) false positive
(c) true negative
(d)* false negative
=> False negatives are the most dangerous failures of a detection system.

?2 [Alert quality] A rule fired 100 times: 80 were real attacks and 20 were benign. The precision is
(a) 20%
(b)* 80%
(c) 100%
(d) 120%
=> Precision = TP / (TP + FP) = 80 / 100 = 80%.
!py assert 80 / (80 + 20) * 100 == num(ans)

?2 [Alert quality] During a month there were 50 real attacks. The rule caught 40 of them. The recall (detection rate) is
(a) 40%
(b)* 80%
(c) 90%
(d) 125%
=> Recall = TP / (TP + FN) = 40 / 50 = 80%. Ten attacks were missed.
!py assert 40 / 50 * 100 == num(ans)

?2 [Alert quality] Tuning a rule to remove all false positives made it miss several real attacks. Which statement describes the trade-off?
(a) precision and recall are unrelated
(b)* making a rule stricter tends to raise precision but can reduce recall
(c) false negatives cannot happen
(d) alerts should never be tuned
=> Detection engineering balances noisy alerts against missed attacks. Measure both.

?1 [Threat intelligence] Which indicator is hardest for an attacker to change?
(a) a file hash
(b) an IP address
(c) a domain name
(d)* behaviour (tactics and techniques)
=> Changing a hash or IP is trivial. Changing how the attack works is expensive, which is why ATT&CK techniques are valuable detection targets.

?1 [Threat intelligence] An IOC (indicator of compromise) is

?1 [Threat intelligence] A canary token is

?1 [Email security] An SPF record lists

?1 [Email security] DKIM provides

?2 [Email security] A message claims to be from "IT Support" but the Return-Path domain is a look-alike (examp1e.com) and SPF fails. The best action is to
(a) click the link to test it

?2 [Email security] A user clicked a link in a phishing email and typed their password. What should be done?

?1 [Incident response] After detecting that a workstation is infected, the first priority is usually

?2 [Incident response] Why isolate a suspected compromised host from the network instead of powering it off?

=> RAM contents disappear at shutdown. Isolation stops the attacker's access while keeping evidence.
