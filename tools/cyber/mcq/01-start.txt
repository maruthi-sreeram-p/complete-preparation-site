?1 [CIA triad] Encrypting a database backup mainly protects which property?
(a) availability
(b) integrity
(c)* confidentiality
(d) non-repudiation
=> Encryption stops people without the key from reading the data, which is confidentiality. It does not by itself prove the data was not changed.

?1 [CIA triad] A hash stored next to a downloadable installer lets users check that the file was not altered. This protects
(a) confidentiality
(b)* integrity
(c) availability
(d) authorisation
=> Comparing the computed hash with the published one detects modification, which is integrity.

?1 [CIA triad] Which control mainly supports availability?
(a) full-disk encryption
(b) a digital signature
(c)* redundant servers and tested backups
(d) a password policy
=> Redundancy and backups keep the service running or recoverable. The others protect confidentiality, integrity or authentication.

?2 [CIA triad] Ransomware encrypts a hospital's patient files, and the attackers also copied them first and threaten to publish them. Which properties were broken?
(a) integrity only
(b) availability only
(c) confidentiality only
(d)* availability and confidentiality
=> The files cannot be used (availability) and the copy leaves the hospital's control (confidentiality). Double extortion combines both.

?1 [CIA triad] Which property do digital signatures and tamper-evident logs support in addition to integrity?
(a) availability
(b)* non-repudiation
(c) obfuscation
(d) redundancy
=> A valid signature proves who produced the data and the signer cannot credibly deny it.

?1 [AAA] "Who are you?" is answered by
(a) authorisation
(b)* authentication
(c) accounting
(d) encryption
=> Authentication verifies identity. Authorisation then decides what that identity may do.

?2 [AAA] A user logs in correctly but the server lets them open another customer's invoice by changing a number in the URL. Which control is missing?
(a) authentication
(b)* authorisation
(c) availability
(d) encryption in transit
=> The user was authenticated. The server failed to check that this user may see that invoice, which is an authorisation (access control) flaw.

?1 [Vocabulary] A query built by joining user input into the SQL string is an example of a
(a) threat
(b) risk
(c)* vulnerability
(d) control
=> It is a weakness. A threat is who or what might exploit it, and a control is the fix, such as prepared statements.

?1 [Vocabulary] The technique or code that takes advantage of a vulnerability is called
(a) a control
(b) an asset
(c) a patch
(d)* an exploit
=> An exploit uses the weakness. A patch fixes it.

?1 [Vocabulary] Risk is best described as
(a) the number of vulnerabilities found
(b)* the likelihood of a threat exploiting a weakness multiplied by the impact
(c) the cost of the firewall
(d) the number of attackers
=> Risk combines how likely a bad event is with how much it would hurt.

?1 [Vocabulary] The attack surface of an application is
(a) the code written by the team only
(b) the servers in the data centre
(c)* every point where an attacker can interact with it or feed it input
(d) the list of known CVEs
=> Endpoints, ports, inputs, dependencies and accounts all count. Removing unused ones reduces it.

?1 [Vocabulary] A vulnerability for which no vendor patch exists yet, and that is already being used, is called a
(a) legacy bug
(b) false positive
(c) hotfix
(d)* zero-day
=> Defenders have had "zero days" to prepare. Mitigations such as virtual patching and network controls are used until a fix ships.

?1 [Risk] Buying cyber insurance is an example of risk
(a) acceptance
(b) avoidance
(c) mitigation
(d)* transfer
=> The financial impact is moved to the insurer. The likelihood of the incident is unchanged.

?1 [Risk] Deciding not to collect customers' government ID numbers at all is risk
(a)* avoidance
(b) acceptance
(c) transfer
(d) mitigation
=> If you never hold the data, it cannot be stolen from you. That removes the risk instead of reducing it.

?1 [Risk] What remains after controls have been applied is called
(a) inherent risk
(b) total risk
(c)* residual risk
(d) latent risk
=> Residual risk is never zero. Management decides whether it is acceptable.

?2 [Risk] An asset is worth 8,00,000 and one incident would destroy 25% of it. The incident is expected once every 4 years. The ALE is
(a) 2,00,000
(b)* 50,000
(c) 1,00,000
(d) 8,00,000
=> SLE = 8,00,000 × 0.25 = 2,00,000. ARO = 1/4 = 0.25. ALE = 2,00,000 × 0.25 = 50,000 per year.

?2 [Risk] A control costs 60,000 a year and reduces an ALE of 1,50,000 to 40,000. The yearly net benefit is
(a) 90,000
(b) 1,10,000
(c)* 50,000
(d) 1,50,000
=> The control removes 1,50,000 − 40,000 = 1,10,000 of expected loss and costs 60,000, so the net benefit is 50,000 per year.

?2 [Risk] A server holds 10 lakh records and the business estimates 3 breaches over 6 years. Which value is the ARO?
(a) 3
(b) 6
(c)* 0.5
(d) 2
=> ARO is expected incidents per year: 3 / 6 = 0.5.

?1 [Threat actors] Reusing a password leaked from one website to log in to a different website is called
(a) password spraying
(b)* credential stuffing
(c) a dictionary attack
(d) phishing
=> Credential stuffing automates logins with leaked username and password pairs. Unique passwords and MFA defeat it.

?1 [Threat actors] Trying one very common password (such as a season and a year) against thousands of accounts is
(a) credential stuffing
(b) brute force against one account
(c)* password spraying
(d) a rainbow table attack
=> Spraying stays under per-account lockout limits by spreading attempts across many accounts.

?1 [Threat actors] Which actor is usually already inside the trust boundary?
(a) a script kiddie
(b)* an insider
(c) a hacktivist
(d) a botnet operator
=> Insiders, malicious or careless, have legitimate access, so perimeter controls alone do not stop them.

?1 [Threat actors] A phishing email aimed at one named finance manager, using details from their LinkedIn profile, is
(a) vishing
(b) smishing
(c) pharming
(d)* spear phishing
=> Targeted phishing is spear phishing. Vishing is by voice call and smishing is by SMS.

?1 [Malware] Which malware spreads across a network by itself, without a user opening a file?
(a) trojan
(b)* worm
(c) spyware
(d) adware
=> A worm replicates automatically. A trojan needs the user to run it, and a virus attaches to a host file.

?1 [Malware] Software that looks like a useful free tool but contains a hidden malicious function is a
(a) worm
(b) rootkit
(c)* trojan
(d) logic bomb
=> A trojan relies on deception, like the wooden horse.

?1 [Malware] Malware designed to hide its own presence and that of other malware deep in the operating system is a
(a) botnet
(b) keylogger
(c) macro virus
(d)* rootkit
=> Rootkits modify the OS or firmware to conceal files, processes and connections.

?2 [Malware] All the files on a finance team's shared drive suddenly have a new extension and a text file asks for payment in cryptocurrency. What is the best first response?
(a)* isolate the affected machines from the network, then follow the incident response plan
(b) pay the ransom immediately
(c) delete the ransom note and restart everything
(d) wait to see whether it spreads
=> Containment comes first so the malware cannot reach more shares and backups. Paying funds crime and guarantees nothing. Restoring from clean backups follows the investigation.

?1 [Attack lifecycle] In the kill chain, sending a malicious attachment to the target is the stage called
(a) reconnaissance
(b) weaponisation
(c)* delivery
(d) installation
=> Delivery is how the payload reaches the victim. Weaponisation is preparing the payload and installation is what happens after it runs.

?1 [Attack lifecycle] MITRE ATT&CK describes attacker behaviour as
(a) a list of CVE numbers
(b) a vendor-specific scoring system
(c)* tactics (goals) and the techniques used to reach them
(d) a firewall rule format
=> For example, the tactic Initial Access includes the technique Phishing. SOC teams map alerts to these IDs.

?1 [Attack lifecycle] After gaining a foothold, moving from one internal machine to another is called
(a) reconnaissance
(b)* lateral movement
(c) exfiltration
(d) weaponisation
=> Lateral movement extends access toward the valuable systems. Segmentation and least privilege slow it down.

?2 [Attack lifecycle] Outbound traffic from an internal server to an unknown IP every 60 seconds, with a tiny payload, most likely indicates
(a) a backup job
(b)* command and control beaconing
(c) a DNS misconfiguration
(d) an expired certificate
=> A regular heartbeat to an external address is typical of an implant checking in. Egress filtering and DNS or proxy logs help detect it.

?1 [Principles] Giving a service account only the permissions it needs for its job is
(a) separation of duties
(b) defence in depth
(c)* least privilege
(d) security through obscurity
=> Least privilege limits what a compromised account can do.

?1 [Principles] Requiring two different people to approve a payment is
(a) least privilege
(b)* separation of duties
(c) zero trust
(d) fail-safe defaults
=> No single person can complete the sensitive action alone, which reduces fraud and mistakes.

?1 [Principles] A permission check throws an exception, and the code returns the page anyway. This breaks the principle of
(a) defence in depth
(b) least privilege
(c)* failing securely
(d) separation of duties
=> On error the safe result is to deny access.

?1 [Principles] Hiding a service on a non-standard port and treating that as the main protection is
(a) defence in depth
(b)* security through obscurity
(c) zero trust
(d) least privilege
=> Obscurity can add a little friction but is not a control by itself. A scan finds the port in minutes.

?1 [Principles] Kerckhoffs's principle says a cryptosystem should remain secure if
(a)* everything except the key is public
(b) the algorithm is kept secret
(c) the key is short
(d) it is only used on a private network
=> Security should depend on the key, not on secrecy of the design. That is why open, reviewed algorithms are preferred.

?2 [Principles] An internal microservice accepts any request from inside the corporate network without authentication because "only our servers can reach it". Which model does this contradict?
(a)* zero trust
(b) risk transfer
(c) non-repudiation
(d) obscurity
=> Zero trust verifies every request regardless of network location. An attacker on any internal machine could call this service.

?1 [Controls] A log-monitoring alert that fires when 50 failed logins occur is which kind of control?
(a) preventive
(b)* detective
(c) corrective
(d) deterrent
=> It notices an attack in progress but does not stop it. Pairing it with an automatic block adds a preventive control.

?1 [Controls] Restoring a database from backup after corruption is a
(a) preventive control
(b) detective control
(c)* corrective control
(d) compensating control
=> Corrective controls repair damage after an incident.

?2 [Controls] A legacy device cannot support MFA, so the company puts it in an isolated network segment and logs all access. This is a
(a) deterrent control
(b)* compensating control
(c) corrective control
(d) transfer of risk
=> A compensating control substitutes for one that cannot be implemented.

?1 [Controls] A security awareness training programme is which category of control by nature?
(a) technical
(b) physical
(c)* administrative
(d) deterrent only
=> Policies, training and procedures are administrative controls. Encryption is technical and locks are physical.

?1 [Threat modelling] In STRIDE, the S stands for
(a) sniffing
(b) SQL injection
(c)* spoofing
(d) session
=> Spoofing means pretending to be someone or something else, which violates authentication.

?1 [Threat modelling] An attacker edits the price field in a request before it reaches the server. Which STRIDE category is this?
(a) spoofing
(b)* tampering
(c) repudiation
(d) information disclosure
=> Changing data in transit or at rest is tampering, a loss of integrity. The fix is to take the price from the server and never from the request.

?1 [Threat modelling] A user claims they never placed an order and there are no logs to prove otherwise. This is a
(a) tampering threat
(b)* repudiation threat
(c) spoofing threat
(d) denial-of-service threat
=> Without audit logs or signatures the system cannot show who did what.

?2 [Threat modelling] An error page prints the full stack trace and the database connection string. Which STRIDE category applies?
(a) elevation of privilege
(b) repudiation
(c)* information disclosure
(d) tampering
=> Leaking internal details lets attackers learn the stack and credentials. Show a generic error and log the details privately.

?1 [Threat modelling] A trust boundary in a data flow diagram is
(a) the place where the data is stored
(b) a firewall product
(c) the edge of the network
(d)* a line where the level of trust changes, such as the internet to your server
=> Data crossing a trust boundary must be authenticated and validated. Most threats appear at these crossings.

?2 [Careers] A Java full stack fresher wants the fastest realistic route into security. Which role uses the existing skills most directly?
(a) GRC auditor
(b) physical security manager
(c)* application security engineer
(d) malware reverse engineer
=> AppSec builds on reading and writing code, HTTP, SQL and frameworks. Reverse engineering needs far deeper low-level skills.

?1 [Law and ethics] Before running a vulnerability scan against a company's systems you must have
(a) the company's public IP address
(b) a free scanner licence
(c)* written permission that defines the scope
(d) the company's logo
=> Written authorisation and a defined scope are what separate a penetration test from an offence.

?2 [Law and ethics] You notice a customer database is publicly downloadable. The best action is to
(a) download a sample to prove it
(b) post about it so the company is pressured
(c)* stop, change nothing, and report it through the company's security contact
(d) fix the permissions yourself
=> Do not access more than needed to confirm, do not change anything, and report responsibly. A security.txt file or a bug bounty page shows where.

?1 [Law and ethics] A security.txt file on a website tells researchers
(a) which ports are open
(b) the list of admin users
(c)* how to contact the site's security team
(d) which cookies are used
=> It is a standard file, usually at /.well-known/security.txt, with a contact address and disclosure policy.

?1 [Principles] Which statement about "defence in depth" is correct?
(a) one very strong firewall is enough
(b)* several independent layers mean one failure is not fatal
(c) it means hiding the architecture
(d) it removes the need for logging
=> Layers such as network filtering, authentication, input validation and least-privilege data access each catch what the others miss.

?2 [Threat modelling] A login form tells the attacker "no such user" for unknown names and "wrong password" for known ones. Which STRIDE category does this enable?
(a) tampering
(b)* information disclosure
(c) repudiation
(d) denial of service
=> The two different messages let an attacker enumerate valid usernames. Return one generic message for both cases.

?1 [Risk] Which of these is a way of mitigating a risk?
(a) buying cyber insurance
(b) deciding the risk is acceptable
(c)* adding multi-factor authentication
(d) stopping the service altogether
=> Mitigation reduces likelihood or impact with a control. Insurance is transfer, acceptance is accept, and stopping the service is avoidance.
