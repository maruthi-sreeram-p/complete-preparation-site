# Secure coding in Java and Spring: 52 original questions. Format: see tools/build_gate.py (?1 recall, ?2 scenario)

?1 [Secure SDLC] "Shifting left" in security means
(a) hiring security staff on the left side of the office
(b)* doing security activities such as threat modelling and scanning earlier in the lifecycle
(c) testing only after release
(d) removing logging
=> Defects found in design or coding are far cheaper to fix than those found in production.

?1 [Secure SDLC] Threat modelling is most valuable during which phase?
(a)* design
(b) after a breach
(c) production monitoring only
(d) retirement
=> It finds flaws before any code exists. It also helps decide which tests to write later.

?1 [Input validation] Which approach to validating a username is the strongest?
(a) reject strings that contain a < or a quote
(b)* accept only the pattern ^[A-Za-z0-9_]{3,30}$
(c) remove characters that look dangerous
(d) validate in JavaScript only
=> An allow-list says exactly what is acceptable. Block lists and stripping can be bypassed, and client-side checks are optional for an attacker.

?1 [Input validation] Validation must be performed
(a) only in the browser
(b)* on the server, because anything from the client can be altered
(c) only on the database
(d) once a month
=> Client-side validation is for user convenience. The server is the only place that attackers cannot skip.

?2 [Input validation] A filter removes "../" from filenames once and then opens the file. An attacker sends "....//....//etc/passwd". The better defence is to
(a) remove "../" twice
(b)* resolve the path, normalise it, and verify it still starts with the base directory
(c) lowercase the string
(d) reject files with dots
=> Deleting patterns creates new patterns. Comparing the final canonical path to the base directory is robust.
!py assert "....//....//etc/passwd".replace("../", "") == "../../etc/passwd"

?2 [Input validation] The regex `(a+)+$` is applied to a long string of a's ending in "!". The risk is
(a) SQL injection
(b)* ReDoS: catastrophic backtracking that burns CPU
(c) XSS
(d) path traversal
=> Nested quantifiers make the number of paths grow exponentially when the match fails. Use simple patterns and bound input length.

?1 [Input validation] Which annotation set belongs on a request DTO field that must be a non-empty e-mail of at most 254 characters?
(a) @Id @Column
(b)* @NotBlank @Email @Size(max = 254)
(c) @Autowired @Value
(d) @Transactional
=> These are Bean Validation constraints, enforced when the controller parameter carries @Valid.

?1 [Input validation] Binding a request body straight into a JPA entity is risky because
(a) entities are slow
(b)* the client can set fields it should not control, such as role or id (mass assignment)
(c) entities cannot be serialised
(d) it needs HTTPS
=> Use request DTOs that contain only the allowed fields and map them to entities explicitly.

?1 [Input validation] Why limit request body, upload and page sizes?
(a)* unbounded input enables denial of service and memory exhaustion
(b) to make the code shorter
(c) to improve colours
(d) to hide errors
=> Size limits are a cheap and effective control. Set limits for JSON depth, array length and file size.

?2 [Input validation] The client sends `price=1` for a product that costs 5000. The server stores that price in the order. The flaw is
(a) XSS
(b)* trusting client-supplied data for a value the server owns; look the price up on the server
(c) weak TLS
(d) missing CORS
=> Anything the user can edit must be revalidated. Prices, roles and totals come from the server.

?1 [Error handling] A production API returns the full Java stack trace on error. This
(a) helps users
(b)* discloses internals such as class names, library versions and queries
(c) improves performance
(d) is required by Spring
=> Return a generic message with a correlation ID, and keep the detail in the log.

?1 [Error handling] "Fail closed" means that when a security check throws an exception, the request is
(a) allowed
(b)* denied
(c) retried forever
(d) redirected to the admin
=> A broken check must not become an open door.

?2 [Error handling] A try/catch around an authorisation call logs nothing and continues execution when an exception occurs. The risk is
(a) a smaller log file
(b)* the action proceeds without authorisation and the failure is invisible
(c) faster responses
(d) none
=> Swallowed exceptions in security code lead to bypasses. Deny and log.

?1 [Secrets] A database password found in application.properties committed to GitHub should be
(a) kept, because the repository is private
(b)* rotated immediately and moved to a secret manager or environment variable
(c) deleted from the next commit only
(d) encoded in Base64
=> The old value remains in Git history and may already have been copied. Rotation is the only reliable fix.

?1 [Secrets] Which tool category finds API keys committed to Git?
(a) DAST
(b) load testing
(c)* secret scanning (for example gitleaks or trufflehog)
(d) code formatting
=> Run it as a pre-commit hook and in CI.

?2 [Secrets] In Spring Boot, which is the safest way to supply a database password to the running container?
(a) hard-code it in the source
(b) put it in the Dockerfile with ENV
(c)* inject it at runtime from a secret manager or an orchestrator secret, referenced as ${DB_PASSWORD}
(d) print it in the logs for the operator
=> Anything baked into the image or repository is available to everyone who can pull it. Runtime injection plus rotation is the pattern.

?2 [Secrets] Which cookie settings are correct for a Spring Boot session cookie?
(a) http-only: false, secure: false
(b)* http-only: true, secure: true, same-site: lax
(c) secure: false, same-site: none
(d) http-only: false, same-site: none
=> HttpOnly blocks script access, Secure forces HTTPS, and SameSite=Lax limits cross-site sending.

?1 [Dependencies] SCA (software composition analysis) tools look for
(a) typing mistakes in your code
(b)* known vulnerabilities in third-party libraries
(c) slow SQL queries
(d) open ports
=> Examples: OWASP Dependency-Check, Dependabot, Snyk.

?1 [Dependencies] An SBOM is
(a) a type of firewall
(b)* a list of all components and versions in your software, which lets you find affected systems quickly
(c) a build error
(d) a database backup
=> When a new critical CVE appears, an SBOM answers "which services use that library?".

?2 [Dependencies] A critical CVE is published for a library used by 40 services. What lets a team respond fastest?
(a) asking each developer from memory
(b)* an up-to-date SBOM and automated dependency scanning in CI
(c) a bigger firewall
(d) disabling logging
=> Inventory plus automation turns a week of searching into a query.

?1 [Dependencies] A package named `reqeusts` (a one-letter misspelling) is added to a project by mistake. This risk is
(a) dependency injection
(b)* typosquatting
(c) SQL injection
(d) a race condition
=> Attackers publish look-alike names carrying malware. Review additions and use trusted registries.

?1 [Java pitfalls] For generating a password reset token you should use
(a) java.util.Random
(b) Math.random()
(c)* java.security.SecureRandom
(d) the current time
=> Only SecureRandom is designed for unpredictable values.

?1 [Java pitfalls] To compare two MAC values or tokens safely you should use
(a) String.equals
(b) ==
(c)* MessageDigest.isEqual (constant-time comparison)
(d) String.compareToIgnoreCase
=> Early-exit comparisons leak timing information that can reveal a valid value byte by byte.

?2 [Java pitfalls] In Java, `int total = 50000 * 50000;` gives
(a) 2500000000
(b)* -1794967296
(c) 0
(d) an exception
=> int overflows silently and wraps around to a negative number. Use Math.multiplyExact or long.
!py assert (((50000 * 50000 + 2**31) % 2**32) - 2**31) == num(ans)

?2 [Java pitfalls] A shop computes `int total = quantity * unitPriceCents` and the attacker orders a huge quantity so the total becomes negative or small. The fix is
(a) a longer variable name
(b)* use long or BigDecimal with Math.multiplyExact and cap the quantity
(c) lowercase the input
(d) use double
=> Exact arithmetic throws on overflow, and business rules should cap quantities.

?2 [Java pitfalls] Why is `0.1 + 0.2 == 0.3` false in Java, and what does it mean for prices?
(a)* binary floating point cannot represent the numbers exactly, so store money as integer cents or BigDecimal
(b) Java has a bug
(c) the compiler optimises it
(d) it is true in Java
=> The sum is 0.30000000000000004.
!py assert (0.1 + 0.2 == 0.3) is False

?1 [Java pitfalls] What is the main danger of calling ObjectInputStream.readObject on data from the network?
(a) it is slow
(b)* an attacker can trigger gadget chains in classes on the classpath, leading to remote code execution
(c) it cannot read bytes
(d) it needs a licence
=> Prefer JSON and DTOs. If native serialisation is unavoidable, use an allow-list ObjectInputFilter.

?1 [Java pitfalls] Which setting reduces XXE risk in an XML parser?
(a) enabling external entities for convenience
(b)* disabling DOCTYPE declarations and external entity resolution
(c) using larger files
(d) switching to HTTP
=> Features such as disallow-doctype-decl turn the dangerous capabilities off.

?1 [Java pitfalls] Building a SpEL expression from user input and evaluating it can lead to
(a) log rotation
(b)* expression injection and code execution
(c) faster startup
(d) stronger encryption
=> Never evaluate user data as an expression. Treat it as plain data.

?1 [Java pitfalls] Public /actuator/env and /actuator/heapdump endpoints in production are
(a) fine
(b)* a serious information disclosure risk
(c) required by Spring
(d) only a performance issue
=> They can expose configuration, secrets in memory and internal details. Expose only health or protect them.

?2 [Java pitfalls] Spring4Shell (CVE-2022-22965) is mostly a lesson about
(a) physical security
(b)* patching quickly and binding requests to DTOs instead of arbitrary objects
(c) password length
(d) DNS
=> Data binding to a rich object graph reached properties it should not have. Fixed in later Spring versions, and DTO binding limits exposure.

?2 [Java pitfalls] A booking system checks that a seat is free and then, in a separate statement, reserves it. Two simultaneous requests both reserve the same seat. This is a
(a) SQL injection
(b)* time-of-check to time-of-use race, fixed with a transaction, lock or unique constraint
(c) XSS
(d) misconfiguration
=> Make check and update atomic, for example UPDATE ... WHERE status='FREE' and check the affected row count.

?1 [Logging] Which should never be written to application logs?
(a) a login failure event
(b) a request ID
(c)* passwords, tokens and full card numbers
(d) the HTTP status code
=> Logs are widely accessible and kept for long. Mask or omit sensitive data.

?2 [Logging] An attacker registers the username "bob\nINFO user admin logged in successfully". The log now contains a forged line. This is
(a) SQL injection
(b)* log injection (log forging), prevented by removing CR/LF or using structured logging
(c) CSRF
(d) clickjacking
=> Newline characters from user data can create fake entries and mislead investigations.
!py assert '\n' not in __import__('re').sub(r'[\r\n\t]', '_', 'bob\nINFO user admin logged in')

?1 [Logging] Which events are worth logging for security?
(a) only server start times
(b)* logins and failures, permission denials, password changes and admin actions
(c) the contents of every request body
(d) nothing, to protect privacy
=> These events support detection and investigation. Include who, what, when, from where and outcome, without secrets.

?1 [Logging] Why send logs to a central, separate system?
(a) to use more disk
(b)* an attacker who compromises a host cannot easily erase the evidence, and teams can correlate events
(c) because logs are public
(d) to speed up the application
=> Centralised, append-only logging preserves evidence and enables alerting.

?2 [Code review] In this snippet: `Files.readAllBytes(Path.of("/data/uploads/" + name))` with `name` from a request. What is the vulnerability?

?2 [Code review] `@PostMapping("/users/{id}") User update(@PathVariable long id, @RequestBody User u) { return repo.save(u); }` has which issues?

?2 [Code review] `String token = Long.toHexString(new Random().nextLong());` used as a password-reset token is weak because

?2 [Code review] Which review question catches broken access control the best?

=> Access control flaws are about missing checks, so you must look for the check, not just the happy path.

?2 [Input validation] A filter rejects any parameter containing "../" but the application URL-decodes the value afterwards. The attacker sends "%2e%2e%2f". What went wrong?
