# Content

Everything the site teaches lives here, separate from the UI code in `src/`.
Adding a roadmap or a topic is just adding files; no code changes needed.

```
content/roadmaps/<roadmap-id>/
  roadmap.json            structure: categories, topics, subtopics, dependencies
  topics/<topic-id>.json  one learning page per topic
```

The folder name is the roadmap id. A topic's page is `topics/<topic id>.json`
(or `topics/<contentId>.json` if the topic sets `contentId`). Topics without a file
show a "no content yet" page and a dashed node on the roadmap.

## roadmap.json

```jsonc
{
  "title": "…",
  "description": "…",
  "placeholder": true,                 // optional: shows a "placeholder data" banner
  "categories": [
    { "id": "cat", "title": "…", "description": "…", "color": "violet" }
    // color: violet | blue | cyan | teal | fuchsia | amber | any #hex; omitted = auto
  ],
  "topics": [
    {
      "id": "unique-id",
      "title": "…",
      "category": "cat",
      "summary": "…",
      "requires": ["other-topic-id"],   // dependencies → connected nodes
      "subtopics": [{ "id": "local-id", "title": "…" }],
      "contentId": "…",                 // optional, defaults to id
      "estimatedMinutes": 45,           // optional
      "position": { "x": 0, "y": 0 },   // optional: overrides automatic layout
      "source": { "document": "x.pdf", "pages": "10-24" }   // optional
    }
  ]
}
```

- **Learning sequence** = dependency order; topics that are ready at the same time follow file order.
- Bad data never crashes the app: unknown/self dependencies, cycles, duplicate ids and unknown
  categories are dropped and listed in a warning box on the dashboard and roadmap.

## topics/<id>.json

```jsonc
{
  "source": { "document": "x.pdf", "pages": "10-24" },
  "sections": [
    {
      "id": "intro",                     // optional anchor id
      "type": "introduction",            // hint for icon/title: introduction | concept | theory | visual |
                                         // architecture | code | example | notes | related | practice | other
      "title": "Introduction",           // optional, defaults from type
      "subtopicId": "local-id",          // optional: links the subtopic checklist to this section
      "blocks": [ /* see below */ ]
    }
  ]
}
```

Only include the sections the source material actually has.

### Blocks

A bare string is a Markdown block.

| type | fields |
| --- | --- |
| `markdown` | `text` (GitHub-flavoured Markdown; fenced code is highlighted) |
| `code` | `language`, `code`, `title?`, `highlight?` ("2-4"), `walkthrough?` `[{ lines, title?, text }]` |
| `diagram` | `format: "mermaid"`, `code`, `title?`, `caption?`, `components?` `[{ name, description }]` |
| `table` | `headers`, `rows`, `caption?` (cells accept inline Markdown) |
| `mcq` | `id` (for saved answers), `items` `[{ t: type, q: markdown, o: options, a: answer index, w: why, svg?, os?: option svgs }]` |
| `callout` | `variant` (note / tip / warning / important), `title?`, `text` |
| `steps` | `title?`, `steps` `[{ title?, text }]` |
| `questions` | `items` `[{ question, hint?, answer, difficulty? }]` |
| `related` | `topics` `[topicId]` |

New block types: add a component and register it in `src/features/content/blockRegistry.jsx`.

See `_examples/placeholder/` for a working example of every block (it is not loaded by the app;
copy it into `roadmaps/` to see it).

### Generated content

`roadmaps/interview-prep/` holds every part and chapter of your PDFs, generated by the scripts in `tools/`
(see the main README). To change the order of the path, edit `tools/learning_path.json` and run
`tools/build_roadmap.py`: stages become categories, and each step requires the previous one.

The frontend stage comes from `tools/build_frontend_topics.py`: it was written for the site, not extracted from a PDF.
Re-running the extractor with `--force` overwrites a topic file, including hand-added code walkthroughs.

## Practice subjects

The **Practice** page reads one file per subject from `content/practice/<subjectId>.json`. Adding a subject is adding a file.

```jsonc
{
  "id": "databases", "title": "…", "group": "Databases", "order": 1, "description": "…",
  "platforms": [{ "name": "LeetCode", "url": "https://…", "note": "…" }],     // "practise this elsewhere" links
  "dataset": { "title": "…", "description": "markdown", "sql": "CREATE TABLE …; INSERT …;" },  // makes "sql" questions runnable
  "questions": [
    { "id": "unique-id", "type": "written", "title": "…", "level": "Easy|Medium|Hard", "prompt": "markdown",
      "hint": "markdown", "answer": "model answer, markdown" },
    { "id": "…", "type": "sql", "title": "…", "prompt": "…", "solution": "SELECT …", "ordered": true },
    { "id": "…", "type": "coding", "title": "…", "level": "…",
      "links": [{ "platform": "LeetCode", "label": "…", "number": 1, "url": "https://leetcode.com/problems/two-sum/", "premium": false }] }
  ]
}
```

- Question ids must be unique across all subjects: answers and ticks are saved under them (in this browser, key `prep-site:practice`).
- **sql** questions run on SQLite compiled to WebAssembly (`sql.js`), in the browser, on a fresh copy of the subject's `dataset` for every run.
  "Check answer" runs the learner's query and `solution` on the same data and compares the results (column names and, unless `ordered` is true, row order are ignored).
- Learners can add their own problems to any subject (a link, or a LeetCode problem number).
- `npm test` runs every `solution` on its dataset and checks the shipped files (`src/lib/practice/content.test.js`).

Sources: `tools/build_practice.py` writes `databases`, `core-java`, `spring-boot`, `kafka` and `system-design` from `tools/practice/*.py`;
`tools/build_dsa_topics.py` writes one `dsa-<topic>` subject per topic of the DSA tree.

## DSA by topic

`roadmaps/dsa-topics/` is a second way into DSA: the 18 topics of NeetCode's roadmap with its dependency graph, a short Java guide for each
(`tools/dsa/NN-<topic>.md`, format in `tools/guide_source.py`) and its NeetCode 150 problems. The topics, edges and problems live in
`tools/dsa/problems.py`; run `python -I tools/build_dsa_topics.py` after editing it. The Java Full Stack tree teaches DSA by pattern; this one is by topic.
